## 현재 구현 범위

표시 변경 통지·상호작용 등록/해제·구독과 예약 정리는 연결했습니다. 준비 전 호출·파괴된 대상·늦은 콜백에 대한 현재 흐름은 [현재 구현과 검증 현황](Docs/개발자용%20설계문서/현재%20구현과%20검증%20현황.md#8-현재-실행과-객체-수명-도식), 구체적인 연결 계약은 [공통 모듈과 객체 수명 설계](Docs/개발자용%20설계문서/공통%20모듈과%20객체%20수명%20설계.md)를 참고합니다.

```mermaid
flowchart LR
    A[DataSheet 검사·배포] --> B[정의 조회·전투 규칙]
    B --> C[타이틀·설정·임시 로딩]
    C --> D[JSON2 맵·플랫폼·몬스터·매복]
    D --> E[전투·HUD·문·출구·재시작]
    F[저장 수집/복원] --> E
    G[엔딩 데이터·공용 컷씬] -.맵 실행 담당·미디어 연결 대기.-> E
```

StageContentSet은 DataSheet에서 배포한 spawn/8001·8002·8003·8005.json을 참조합니다. 현재 산길 8002는 상한 9·실제 9마리, 협곡 8003은 상한 30·실제 30마리이며 협곡 중 4마리가 매복입니다. 최대 수는 JSON별 MaxMonsterCount에서 설정하고 전체 배치 합계를 배포 전에 검사합니다. 플랫폼별 Points는 FormatVersion2의 앵커 기준 좌표입니다. 맵·몬스터를 재사용하는 실제 풀은 아직 없습니다. 회피 글자는 별도 소형 풀로 재사용하며 몬스터 풀 구현과 구분합니다.

테스트·시연 수동/자동 공용10슬롯·날짜 내림차순·번호 비표시, 출시 자동1슬롯이라는 사용자 기준을 유지합니다. 현재 테스트 맵의 새 게임 최초 기록·최신/선택 기록 복원·F5·서낭당 자동 저장을 연결했습니다. 관문은 GateConfig 정수 ID로 저장합니다. 개별 처치 기록과 저장 복원은 연결했습니다. 실제 Unity 왕복·사망·저장 회귀와 연속 필드·별도 보스 씬 검증은 후속입니다.

현재 해체는 임시 900ms 대신 플레이어와 대상 애니메이션의 긴 쪽 완료 시간을 사용하며 일반몹도 기존 실행 계약을 사용합니다. 재입장/복귀·관문 우회·명중 진동·발 정렬의 최신 빌드 검증은 별도로 필요합니다. 사망 불은 설정0으로 끈 상태입니다. 회의의 시각 개선·튜토리얼·타이틀 새 시안과 실제 빌드 회귀 검사가 남았습니다. 맵19개 PC BC7은 설정 적용이며 용량·화질 측정 결과는 아닙니다.

## 데이터 추가부터 실행까지

```mermaid
flowchart TD
    A[DataSheet: 새 파일·탭의 기존 규칙 작성] --> B[배포 실행파일 실행]
    B --> C[검사·데이터 추출·없는 정의 클래스 최초 생성]
    C --> D[자동 로딩 계획 생성·클라이언트 호환성 검사]
    D --> E[클라이언트에 배포]

```

새 파일·탭을 추가할 때 클라이언트 초기화 목록을 수동 수정하지 않습니다. `Assets/3.Script/Data/Generated/GeneratedDataLoadPlan.cs`가 시트 규칙에서 생성됩니다. 코드와 에셋이 반영된 후 실행하면 새 테이블도 읽기·변환·저장소 등록까지 자동 연결됩니다. 이미 빌드한 실행파일에 새 타입을 추가하려면 클라이언트 재빌드가 필요합니다.

| 배포 대상 | 처리 방식 |
| --- | --- |
| CSV·JSON | 매번 갱신. 삭제한 탭의 이전 배포 데이터 정리 |
| 데이터 정의 C#·상태 열거형 | 해당 파일이 없을 때만 최초 추가. 기존 파일 보존 |
| 자동 로딩 계획 | 매번 갱신. 수동 수정 금지 |
| Unity 메타 파일 | 유지 |

기존 시트의 컬럼·생성자·상태 식별자 변경은 기존 클래스·열거형에 자동 반영되지 않습니다. 생성 파일 머리의 "다시 배포하세요" 안내만으로는 갱신되지 않으므로, 데이터 공급 담당과 스키마 변경을 맞춘 뒤 개발자가 함께 수정합니다. 자동 로딩 계획은 수동 수정하지 않습니다. 새 데이터로 실제 게임 동작을 만드는 일은 해당 기능의 구현 범위입니다.

## 초기화 순서와 사용

```mermaid
sequenceDiagram
    participant S as 씬 초기화 컴포넌트
    participant P as 자동 로딩 계획
    participant C as 저장소
    participant G as 게임 기능
    S->>P: 초기화 시작
    P->>C: 공통 스탯 CSV 읽기·변환·등록
    P->>C: 나머지 CSV 전체 읽기·변환·등록
    P->>C: JSON 읽기·변환·등록
    C-->>S: 완성된 조회 묶음
    S-->>G: 초기화 완료 이벤트
```

기본 씬의 `GameDataInitializer`가 시작 단계에서 초기화합니다. 다른 시작 씬에서는 **인귀 → 데이터 → 현재 씬에 초기화 연결**을 실행하고 씬을 저장합니다. 참조 목록 수동 갱신은 **인귀 → 데이터 → 에셋 목록 갱신**입니다.

일반 정의는 `ID`, 상태 묶음은 `UnitID`로 조회합니다. 소비자는 완료 이벤트를 구독하고, 이미 초기화된 경우 현재 `Data`를 확인하며, 비활성화 시 구독을 해제합니다. 자세한 코드는 [인수인계 가이드](Docs/%EA%B0%9C%EB%B0%9C%EC%9E%90%EC%9A%A9%20%EC%84%A4%EA%B3%84%EB%AC%B8%EC%84%9C/%EB%8D%B0%EC%9D%B4%ED%84%B0%20%EA%B3%84%EC%B8%B5%20%EC%9D%B8%EC%88%98%EC%9D%B8%EA%B3%84%20%EA%B0%80%EC%9D%B4%EB%93%9C.md)를 따릅니다. 전역 정적 저장소는 사용하지 않습니다.

데이터 정의는 읽기 전용 설정입니다. 현재 체력·위치·타이머·대상은 캐릭터 런타임이 별도로 소유합니다. 클라이언트에 배포 전 데이터 검사기를 중복 구현하지 않습니다.

## 수치·협업 원칙

기본 수치는 정수, 시간은 밀리초, 확률 분모는 10000입니다. 이동 값은 시트의 타일×100 단위를 따르고 엔진 경계에서 변환합니다. 정수 나눗셈 잔여량·반올림·범위는 각 런타임 기능에서 정의합니다. 주석·설명·로그·직접 작성한 오류 안내는 한글로 작성합니다.

공통 계약은 인터페이스로 표현하고 의존성은 명시적으로 주입합니다. 공통 스탯은 추상 기반 클래스에 한 번만 선언합니다. 상태 팩토리는 상태 구성에 사용하며 캐릭터 자체의 팩토리는 이번 설계에 두지 않습니다.
