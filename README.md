# Human_Ghost-

싱글플레이 2D 액션게임 클라이언트입니다. 데이터는 형제 프로젝트인 DataSheet에서 검사·배포하고, 클라이언트는 읽기·객체 변환·조회·게임 기능 연결을 담당합니다.

디스코드 머지 알림 설정과 연결 테스트는 [알림 가이드](Docs/%EB%94%94%EC%8A%A4%EC%BD%94%EB%93%9C%20%EC%95%8C%EB%A6%BC%20%EC%84%A4%EC%A0%95%20%EC%95%88%EB%82%B4.md)를 참고합니다.

## 현재 구현 범위

플레이어 체력 표시에는 `HealthDisplayConfig` 설정 테이블을 연결했습니다. 기획자는 프리팹 키·앵커 이름·크기·표시 여부를 데이터로 지정하고, 위치는 씬 또는 부모 프리팹의 빈 앵커를 옮겨 조정합니다. `HealthDisplayGroup.Create`가 행 전체를 적용하며 체력 변경 때만 갱신합니다. 실제 씬의 조립자는 준비된 데이터·플레이어·인스턴스별 앵커·프리팹 목록을 전달하고 종료 시 그룹을 정리합니다. 기존 GameplayPreview에 자동 부착한 상태는 아닙니다.

앞으로 프리팹 스폰은 앵커 이름 기반을 기본으로 합니다. 부모 프리팹 내부 앵커를 사용할 때는 부모 생성 완료 후 해당 인스턴스에서 수집합니다. 공통 이름 연결과 기능별 풀링·활성화·회수는 분리합니다.

씬 연결 창구인 `HealthDisplayHost`의 Connect·Disconnect와 활성 수명까지 준비했습니다. 실제 씬·기존 프리팹 부착은 현재 작업 업로드와 다른 작업자 코드 확인 이후로 보류합니다. 준비된 데이터·플레이어·프리팹 목록·앵커를 호출자가 전달하며 자동 장면 검색·매 프레임 준비 확인은 하지 않습니다.

```mermaid
flowchart LR
    A[검사된 CSV·JSON] --> B[문자열 읽기]
    B --> C[공통 생성자 연결·객체 변환]
    C --> D[읽기 전용 저장소]
    D --> E[전체 초기화 완료 알림]
    E --> F[플레이어·보스·일반 몬스터 코어]
    F --> P[임시 확인 장면]
    P --> N[후속: 운영 물리·표현·스폰]
```

CSV·JSON 읽기, 공통 객체 변환, 식별자 조회 저장소, 자동 로딩 계획 실행, 씬 초기화·취소 수명, 빌드용 데이터 에셋 참조 연결을 구현했습니다. 게임플레이 코어는 공통 상태, 이동/점프 요청, New Input System, 공격/콤보, 구르기/스태미나/피격/무적, 보스 체세/해체 API까지 구현했습니다. 허수귀·지게귀 AI와 잡기·구속·돌진·벽 충돌 허점 코어, 패턴 설정과 프리팹도 있습니다. GameplayPreview 장면에서 임시 이동·판정·상태 표시를 연결했습니다. 보스 내려찍기·2연타·페이즈2 문 돌진 실행 코어, HP50% 페이즈 수치 전환과 확률 회피·치명 판정도 구현했습니다. 운영 물리·카메라·히트박스·애니메이션·보스 자동 AI(패턴 선택)·보스 이동/벽 관측 연결·사슬 당기기·전환 연출·보스 패턴 운영 설정·변종 고유 동작·스폰·풀링은 후속 범위입니다. 현재 상태에 불필요한 상태 Factory는 추가하지 않았습니다.

## 데이터 추가부터 실행까지

```mermaid
flowchart TD
    A[DataSheet: 새 파일·탭의 기존 규칙 작성] --> B[배포 실행파일 실행]
    B --> C[검사·데이터 추출·없는 정의 클래스 최초 생성]
    C --> D[자동 로딩 계획 생성·클라이언트 호환성 검사]
    D --> E[클라이언트에 배포]
    E --> F[Unity: 코드 반영·에셋 참조 목록 갱신]
    F --> G[초기화 객체가 생성 계획 실행]
    G --> H[식별자로 새 테이블 조회]
```

새 파일·탭을 추가할 때 클라이언트 초기화 목록을 수동 수정하지 않습니다. `Assets/3.Script/Data/Generated/GeneratedDataLoadPlan.cs`가 시트 규칙에서 생성됩니다. 코드와 에셋이 반영된 후 실행하면 새 테이블도 읽기·변환·저장소 등록까지 자동 연결됩니다. 이미 빌드한 실행파일에 새 타입을 추가하려면 클라이언트 재빌드가 필요합니다.

| 배포 대상 | 처리 방식 |
| --- | --- |
| CSV·JSON | 매번 갱신. 삭제한 탭의 이전 배포 데이터 정리 |
| 데이터 정의 C#·상태 열거형 | 해당 파일이 없을 때만 최초 추가. 기존 파일 보존 |
| 자동 로딩 계획 | 매번 갱신. 수동 수정 금지 |
| Unity 메타 파일 | 유지 |

기존 시트의 컬럼·생성자·상태 식별자 변경은 기존 클래스·열거형에 자동 반영되지 않습니다. 생성 파일 머리의 "다시 배포하세요" 안내만으로는 갱신되지 않으므로, 데이터 공급 담당과 스키마 변경을 맞춘 뒤 개발자가 함께 수정합니다. 자동 로딩 계획은 수동 수정하지 않습니다. 새 데이터로 실제 게임 동작을 만드는 일은 해당 기능의 구현 범위입니다.

## 초기화 순서와 사용

```mermaid
sequenceDiagram
    participant S as 씬 초기화 컴포넌트
    participant P as 자동 로딩 계획
    participant C as 저장소
    participant G as 게임 기능
    S->>P: 초기화 시작
    P->>C: 공통 스탯 CSV 읽기·변환·등록
    P->>C: 나머지 CSV 전체 읽기·변환·등록
    P->>C: JSON 읽기·변환·등록
    C-->>S: 완성된 조회 묶음
    S-->>G: 초기화 완료 이벤트
```

기본 씬의 `GameDataInitializer`가 시작 단계에서 초기화합니다. 다른 시작 씬에서는 **인귀 → 데이터 → 현재 씬에 초기화 연결**을 실행하고 씬을 저장합니다. 참조 목록 수동 갱신은 **인귀 → 데이터 → 에셋 목록 갱신**입니다.

일반 정의는 `ID`, 상태 묶음은 `UnitID`로 조회합니다. 소비자는 완료 이벤트를 구독하고, 이미 초기화된 경우 현재 `Data`를 확인하며, 비활성화 시 구독을 해제합니다. 자세한 코드는 [인수인계 가이드](Docs/%EB%8D%B0%EC%9D%B4%ED%84%B0%20%EA%B3%84%EC%B8%B5%20%EC%9D%B8%EC%88%98%EC%9D%B8%EA%B3%84%20%EA%B0%80%EC%9D%B4%EB%93%9C.md)를 따릅니다. 전역 정적 저장소는 사용하지 않습니다.

데이터 정의는 읽기 전용 설정입니다. 현재 체력·위치·타이머·대상은 캐릭터 런타임이 별도로 소유합니다. 클라이언트에 배포 전 데이터 검사기를 중복 구현하지 않습니다.

## 수치·협업 원칙

기본 수치는 정수, 시간은 밀리초, 확률 분모는 10000입니다. 이동 값은 시트의 타일×100 단위를 따르고 엔진 경계에서 변환합니다. 정수 나눗셈 잔여량·반올림·범위는 각 런타임 기능에서 정의합니다. 주석·설명·로그·직접 작성한 오류 안내는 한글로 작성합니다.

공통 계약은 인터페이스로 표현하고 의존성은 명시적으로 주입합니다. 공통 스탯은 추상 기반 클래스에 한 번만 선언합니다. 상태 팩토리는 상태 구성에 사용하며 캐릭터 자체의 팩토리는 이번 설계에 두지 않습니다.
