## 2. 현재 진행 상태

2026-11-13 기준, 주요 기능을 현재 맵에 연결했고 콘텐츠·연출 통합과 실제 시연 검증을 보강하는 단계입니다. 필드 효과·몬스터 공통 면역·시트 기반 enum 갱신을 추가했고 NPC·대사 원본과 새 오류 문구를 배포했습니다.

~~~mermaid
flowchart LR
    A[데이터 공급·자동화] --> B[주요 게임 기능 연결]
    B --> C[콘텐츠·연출 통합]
    C --> D[실제 Play·빌드 완주]
~~~

데이터 공급·코드·연결·자동 검사·실제 수용을 나눠 기록합니다. 기능 연결 비율을 게임 전체 완성률이나 개인 기여율로 사용하지 않습니다. 최신 상태와 추가·변경 사항은 [현황](Docs/개발자용%20설계문서/현재%20구현과%20검증%20현황.md), 완료 조건은 [남은 작업](Docs/개발자용%20설계문서/남은%20구현과%20검증%20작업.md) 한곳에서 관리합니다.

## 3. 프로젝트와 데이터 자동화

~~~mermaid
flowchart LR
    A[형제 DataSheet 원본] --> B[DeployData.exe 발견·검사·추출]
    B --> C[데이터·최초 정의·enum·로딩 계획 배포]
    C --> D[Unity 반영·CSV 다음 테이블 JSON]
    D --> E[명시적 게임 기능 조립]
~~~

- DataSheet와 Human_Ghost-는 같은 부모 폴더에 둡니다.
- 새 xlsx·탭은 기존 상단 규칙을 읽어 자동 처리합니다.
- 같은 형식의 별도 JSON은 자동 발견·검사·배포합니다. 새 형식은 검사 규칙이 없으면 중단합니다.
- 일반 정의 C#는 최초 생성 후 보존하며 스키마 변경은 개발자가 함께 맞춥니다.
- 생성 enum·StateKey·자동 로딩 계획은 매번 갱신합니다.
- 별도 JSON의 배포 성공은 새 게임 기능·프리팹·씬의 최초 연결 완료가 아닙니다.
- EXE 실행 이후가 자동이며 파일 저장 감시·Git 푸시·게임 빌드는 별도입니다.

| 위치 | 책임 |
| --- | --- |
| Assets/3.Script/Data·Common | 정의·읽기·변환·조회·초기화 |
| Assets/3.Script/Core | Unity와 분리한 규칙·실행 상태 |
| Assets/3.Script/Adapters·Presentation | 입력·리소스·엔진·화면 연결 |
| Assets/3.Script/Preview | 현재 게임 씬의 조립과 연결 |
| Assets/3.Script/FireBase | 게임 이벤트 독립 기록·전송 |
| 형제 DataSheet/Tools | .NET 10·최신 안정 C# 도구. 생성 결과는 별도 C# 9 검사 |

## 4. 실행·빌드·확인

현재 Unity 버전은 ProjectVersion.txt를 따릅니다. 주요 실행 씬은 Title·MapDohwagolTest이며, SampleScene은 데이터 예제입니다. 새 데이터·코드의 Unity 반영이 끝난 뒤 실행합니다. 이미 받은 게임 실행파일은 원본 변경으로 갱신되지 않습니다.

~~~mermaid
flowchart LR
    A[로컬 검사] --> B[Git에 필요한 변경 반영]
    B --> C[GitHub 수동 빌드 선택]
    C --> D[결과물 다운로드·실행 확인]
~~~

GitHub의 Windows 게임 빌드에서 development/release를 선택합니다. Windows 64비트, 기본 테스트, 결과물 7일 보관, 빌드 전용 디스코드 공지를 사용합니다. 매 푸시 게임 빌드·임의 리비전 입력 기능은 현재 없습니다. 상세는 [빌드 안내](Docs/기획자용%20안내문서/GitHub%20빌드와%20디스코드%20공지%20사용%20안내.md)를 봅니다.

~~~powershell
./Tools/Verify-Project.ps1 -CompileUnity
~~~

자동 검사와 엔진 참조 컴파일은 실제 Play·장치·새 실행파일 완주를 대신하지 않습니다. 검사 방식은 [기획자 안내](Docs/기획자용%20안내문서/기획자용%20프로젝트%20검사%20사용%20안내.md), 결과는 현황 문서에 기록합니다.
