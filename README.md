# Human_Ghost-

싱글플레이 2D 액션게임 클라이언트입니다. 데이터는 형제 프로젝트인 DataSheet에서 검사·배포하고, 클라이언트는 읽기·객체 변환·조회·게임 기능 연결을 담당합니다.

디스코드 머지 알림 설정과 연결 테스트는 [알림 가이드](Docs/DiscordNotifications.md)를 참고합니다.

## 현재 구현 범위

```mermaid
flowchart LR
    A[검사된 CSV·JSON] --> B[문자열 읽기]
    B --> C[공통 생성자 연결·객체 변환]
    C --> D[읽기 전용 저장소]
    D --> E[전체 초기화 완료 알림]
    E --> F[다음 작업: 캐릭터 런타임·상태·표현]
```

CSV·JSON 읽기, 공통 객체 변환, 식별자 조회 저장소, 자동 로딩 계획 실행, 씬 초기화·취소 수명, 빌드용 데이터 에셋 참조 연결을 구현했습니다. 게임플레이 코어는 공통 상태, 이동/점프 요청, New Input System, 공격/콤보, 구르기/스태미나/피격/무적, 보스 체세/해체 API까지 구현했습니다. 설정 에셋과 플레이어/보스 프리팹을 제공하며 실제 물리·카메라·히트박스/표현·AI/풀링 연결은 후속 범위입니다. 현재 상태에 불필요한 상태 Factory는 추가하지 않았습니다.

## 프로젝트 배치와 폴더

두 저장소는 같은 부모 폴더 아래에 둡니다. 클라이언트는 Unity `6000.2.8f1`을 사용합니다. JSON 읽기는 Unity의 Newtonsoft JSON 패키지 `3.2.2`를 사용하며 에디터에서 패키지를 복원합니다.

```text
공통 부모 폴더/
├── DataSheet/
│   ├── tables/
│   └── DeployData.exe
└── Human_Ghost-/
    ├── Assets/
    │   ├── 1.Scene/SampleScene.unity
    │   ├── 3.Script/
    │   │   ├── Common/              ← 입력 계약·형식 읽기
    │   │   └── Data/
    │   │       ├── Mapping/         ← 공통 객체 변환
    │   │       ├── Storage/         ← 읽기 전용 저장소
    │   │       ├── Infrastructure/  ← 초기화·에셋 입력·수명
    │   │       └── Generated/       ← 자동 로딩 계획
    │   ├── Data/                    ← CSV·JSON·데이터 에셋 목록
    │   └── Editor/Data/             ← 에셋 목록 갱신·씬 연결
    ├── Docs/
    └── Tools/Verify-Data.ps1
```

## 데이터 추가부터 실행까지

```mermaid
flowchart TD
    A[DataSheet: 새 파일·탭의 기존 규칙 작성] --> B[배포 실행파일 실행]
    B --> C[검사·데이터 추출·없는 정의 클래스 최초 생성]
    C --> D[자동 로딩 계획 생성·클라이언트 호환성 검사]
    D --> E[클라이언트에 배포]
    E --> F[Unity: 코드 반영·에셋 참조 목록 갱신]
    F --> G[초기화 객체가 생성 계획 실행]
    G --> H[식별자로 새 테이블 조회]
```

새 파일·탭을 추가할 때 클라이언트 초기화 목록을 수동 수정하지 않습니다. `Assets/3.Script/Data/Generated/GeneratedDataLoadPlan.cs`가 시트 규칙에서 생성됩니다. 코드와 에셋이 반영된 후 실행하면 새 테이블도 읽기·변환·저장소 등록까지 자동 연결됩니다. 이미 빌드한 실행파일에 새 타입을 추가하려면 클라이언트 재빌드가 필요합니다.

| 배포 대상 | 처리 방식 |
| --- | --- |
| CSV·JSON | 매번 갱신. 삭제한 탭의 이전 배포 데이터 정리 |
| 데이터 정의 C#·상태 열거형 | 해당 파일이 없을 때만 최초 추가. 기존 파일 보존 |
| 자동 로딩 계획 | 매번 갱신. 수동 수정 금지 |
| Unity 메타 파일 | 유지 |

기존 시트의 컬럼·생성자·상태 식별자 변경은 기존 클래스·열거형에 자동 반영되지 않습니다. 개발자가 함께 수정해야 합니다. 새 데이터로 실제 게임 동작을 만드는 일은 해당 기능의 구현 범위입니다.

## 초기화 순서와 사용

```mermaid
sequenceDiagram
    participant S as 씬 초기화 컴포넌트
    participant P as 자동 로딩 계획
    participant C as 저장소
    participant G as 게임 기능
    S->>P: 초기화 시작
    P->>C: 공통 스탯 CSV 읽기·변환·등록
    P->>C: 나머지 CSV 전체 읽기·변환·등록
    P->>C: JSON 읽기·변환·등록
    C-->>S: 완성된 조회 묶음
    S-->>G: 초기화 완료 이벤트
```

기본 씬의 `GameDataInitializer`가 시작 단계에서 초기화합니다. 다른 시작 씬에서는 **인귀 → 데이터 → 현재 씬에 초기화 연결**을 실행하고 씬을 저장합니다. 참조 목록 수동 갱신은 **인귀 → 데이터 → 에셋 목록 갱신**입니다.

일반 정의는 `ID`, 상태 묶음은 `UnitID`로 조회합니다. 소비자는 완료 이벤트를 구독하고, 이미 초기화된 경우 현재 `Data`를 확인하며, 비활성화 시 구독을 해제합니다. 자세한 코드는 [인수인계 가이드](Docs/DataHandoff.md)를 따릅니다. 전역 정적 저장소는 사용하지 않습니다.

데이터 정의는 읽기 전용 설정입니다. 현재 체력·위치·타이머·대상은 캐릭터 런타임이 별도로 소유합니다. 클라이언트에 배포 전 데이터 검사기를 중복 구현하지 않습니다.

## 수치·협업 원칙

기본 수치는 정수, 시간은 밀리초, 확률 분모는 10000입니다. 이동 값은 시트의 타일×100 단위를 따르고 엔진 경계에서 변환합니다. 정수 나눗셈 잔여량·반올림·범위는 각 런타임 기능에서 정의합니다. 주석·설명·로그·직접 작성한 오류 안내는 한글로 작성합니다.

공통 계약은 인터페이스로 표현하고 의존성은 명시적으로 주입합니다. 공통 스탯은 추상 기반 클래스에 한 번만 선언합니다. 상태 팩토리는 상태 구성에 사용하며 캐릭터 자체의 팩토리는 이번 설계에 두지 않습니다.

## 검증과 남은 확인

최근 개발용 검사 674개와 설치된 Unity 모듈 참조 컴파일이 통과했습니다. 새 CSV 탭 2개·JSON 탭 1개의 자동 등록·초기화·식별자 조회는 DataSheet 통합 검사에서 확인했습니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tools/Verify-Data.ps1 -CompileUnity
```

검사 도구 실행에는 개발 PC의 .NET 10 SDK와 설치된 Unity가 필요합니다. Unity 설치 위치가 다르면 `-UnityEditorPath`로 에디터 실행파일을 지정합니다. 임시 빌드 결과는 종료 시 정리합니다.

실제 Unity 플레이·플레이어 빌드 검증은 아직 완료하지 못했습니다. 앞선 일괄 실행은 라이선스 연결 단계에서 종료됐으므로 모듈 참조 컴파일 성공과 실제 실행 성공을 구분합니다. 또한 완료 이벤트 수신자의 예외가 뒤의 수신자에게 영향을 줄 수 있어 오류 격리 정책 보완이 남아 있습니다.

최초 자동 로딩 전환 시 클라이언트와 DataSheet 실행파일을 함께 최신화합니다. 도구 변경은 소스와 배포 EXE를 함께 공유합니다. 작성 기준일: 2026-10-30.
