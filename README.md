# Human_Ghost-

2026-11-05 오류 팝업: TitleScreen 프리팹과 MapDohwagolTest에 자동 수집·입력 차단·독립 일시정지를 연결했습니다. 새 씬의 Inspector 설정과 확인 순서는 [기획자 안내](Docs/기획자용%20에러%20팝업%20사용%20안내.md)를 참고합니다. 데이터911·코어604·기존 CS0414 제외 개발 분기 참조 컴파일 통과, 실제 Unity 표시 검증은 별도입니다.

2026-11-04 최신 풀 `c7100e3`: JSON2 맵·몬스터·매복, 타이틀/설정·임시 로딩·전투 화면과 회의 버그 수정이 테스트 씬에 연결돼 있습니다. 저장 실제 복원·컷씬 표시·정식 장부방·풀링·최종 아트는 후속입니다. 데이터875·코어600 통과, 엄격한 엔진 참조 컴파일은 `_exitAnchor` 미사용으로 실패했습니다. [현재 구현과 검증 현황](Docs/현재%20구현과%20검증%20현황.md), [남은 작업과 회의 반영](Docs/남은%20구현과%20검증%20작업.md), [기획 대조](Docs/기획%20완료%20기준%20점검표.md)를 기준으로 사용합니다.

## 현재 구현 범위

```mermaid
flowchart LR
    A[DataSheet 검사·배포] --> B[정의 조회·전투 규칙]
    B --> C[타이틀·설정·임시 로딩]
    C --> D[JSON2 맵·플랫폼·몬스터·매복]
    D --> E[전투·HUD·문·출구·재시작]
    F[저장·컷씬 코어] -.실제 복원·표시 연결 대기.-> E
```

StageContentSet은 현재 SpawnTemp의 맵2·3 각30마리와 협곡 매복4마리를 직접 참조합니다. DataSheet 정식 배포본은 각4마리이며 자동 참조 갱신·원본 통합은 후속입니다. 플랫폼별 Points는 FormatVersion2의 앵커 기준 좌표입니다. 실제 풀은 아직 없습니다.

테스트·시연 수동/자동 공용10슬롯·날짜 내림차순·번호 비표시, 출시 자동1슬롯이라는 사용자 기준을 유지합니다. 실제 F5 연결은 저장 팝업·관문 키 계약 수정과 상태 수집/복원 연결이 필요합니다. 코드가 있다는 사실만으로 현재 씬에서 저장·이어하기가 완성됐다고 보지 않습니다.

최신 수정은 해체 임시900ms 종료·재입장/복귀·관문 우회·명중 진동·발 정렬을 포함합니다. 사망 불은 설정0으로 끈 상태입니다. 회의의 시각 개선·튜토리얼·타이틀 새 시안과 실제 빌드 회귀 검사가 남았습니다. 맵19개 PC BC7은 설정 적용이며 용량·화질 측정 결과는 아닙니다.

## 데이터 추가부터 실행까지

```mermaid
flowchart TD
    A[DataSheet: 새 파일·탭의 기존 규칙 작성] --> B[배포 실행파일 실행]
    B --> C[검사·데이터 추출·없는 정의 클래스 최초 생성]
    C --> D[자동 로딩 계획 생성·클라이언트 호환성 검사]
    D --> E[클라이언트에 배포]
    E --> F[Unity: 코드 반영·에셋 참조 목록 갱신]
    F --> G[초기화 객체가 생성 계획 실행]
    G --> H[식별자로 새 테이블 조회]
```

새 파일·탭을 추가할 때 클라이언트 초기화 목록을 수동 수정하지 않습니다. `Assets/3.Script/Data/Generated/GeneratedDataLoadPlan.cs`가 시트 규칙에서 생성됩니다. 코드와 에셋이 반영된 후 실행하면 새 테이블도 읽기·변환·저장소 등록까지 자동 연결됩니다. 이미 빌드한 실행파일에 새 타입을 추가하려면 클라이언트 재빌드가 필요합니다.

| 배포 대상 | 처리 방식 |
| --- | --- |
| CSV·JSON | 매번 갱신. 삭제한 탭의 이전 배포 데이터 정리 |
| 데이터 정의 C#·상태 열거형 | 해당 파일이 없을 때만 최초 추가. 기존 파일 보존 |
| 자동 로딩 계획 | 매번 갱신. 수동 수정 금지 |
| Unity 메타 파일 | 유지 |

기존 시트의 컬럼·생성자·상태 식별자 변경은 기존 클래스·열거형에 자동 반영되지 않습니다. 생성 파일 머리의 "다시 배포하세요" 안내만으로는 갱신되지 않으므로, 데이터 공급 담당과 스키마 변경을 맞춘 뒤 개발자가 함께 수정합니다. 자동 로딩 계획은 수동 수정하지 않습니다. 새 데이터로 실제 게임 동작을 만드는 일은 해당 기능의 구현 범위입니다.

## 초기화 순서와 사용

```mermaid
sequenceDiagram
    participant S as 씬 초기화 컴포넌트
    participant P as 자동 로딩 계획
    participant C as 저장소
    participant G as 게임 기능
    S->>P: 초기화 시작
    P->>C: 공통 스탯 CSV 읽기·변환·등록
    P->>C: 나머지 CSV 전체 읽기·변환·등록
    P->>C: JSON 읽기·변환·등록
    C-->>S: 완성된 조회 묶음
    S-->>G: 초기화 완료 이벤트
```

기본 씬의 `GameDataInitializer`가 시작 단계에서 초기화합니다. 다른 시작 씬에서는 **인귀 → 데이터 → 현재 씬에 초기화 연결**을 실행하고 씬을 저장합니다. 참조 목록 수동 갱신은 **인귀 → 데이터 → 에셋 목록 갱신**입니다.

일반 정의는 `ID`, 상태 묶음은 `UnitID`로 조회합니다. 소비자는 완료 이벤트를 구독하고, 이미 초기화된 경우 현재 `Data`를 확인하며, 비활성화 시 구독을 해제합니다. 자세한 코드는 [인수인계 가이드](Docs/%EB%8D%B0%EC%9D%B4%ED%84%B0%20%EA%B3%84%EC%B8%B5%20%EC%9D%B8%EC%88%98%EC%9D%B8%EA%B3%84%20%EA%B0%80%EC%9D%B4%EB%93%9C.md)를 따릅니다. 전역 정적 저장소는 사용하지 않습니다.

데이터 정의는 읽기 전용 설정입니다. 현재 체력·위치·타이머·대상은 캐릭터 런타임이 별도로 소유합니다. 클라이언트에 배포 전 데이터 검사기를 중복 구현하지 않습니다.

## 수치·협업 원칙

기본 수치는 정수, 시간은 밀리초, 확률 분모는 10000입니다. 이동 값은 시트의 타일×100 단위를 따르고 엔진 경계에서 변환합니다. 정수 나눗셈 잔여량·반올림·범위는 각 런타임 기능에서 정의합니다. 주석·설명·로그·직접 작성한 오류 안내는 한글로 작성합니다.

공통 계약은 인터페이스로 표현하고 의존성은 명시적으로 주입합니다. 공통 스탯은 추상 기반 클래스에 한 번만 선언합니다. 상태 팩토리는 상태 구성에 사용하며 캐릭터 자체의 팩토리는 이번 설계에 두지 않습니다.

## 검증과 남은 확인

2026-11-03 전체 점검: 클라이언트 데이터875개·코어462개 통과, Unity 모듈 참조 컴파일 경고0·오류0. DataSheet EXE --check는17탭·정의21·계획1로 통과했습니다. 이번 점검에서 실제 Unity Play·최종 실행파일·GitHub 원격 실행을 재검증하지 않았습니다. 과거 Play 검사와 최신 결과는 [검증 현황](Docs/현재%20구현과%20검증%20현황.md)에서 구분합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tools/Verify-Project.ps1
```

기본 통합 검사는 .NET 10 SDK가 필요하고 Unity 설치 없이 실행합니다. `-CompileUnity`는 설치된 엔진을 참조한 컴파일을 추가합니다. Unity 위치는 `-UnityEditorPath`로 지정합니다. 임시 결과는 종료 시 정리합니다. 컴파일 통과와 프리팹 표시·실제 입력·플레이어 빌드 성공은 별도입니다.

GitHub의 Develop 푸시는 검사·개발 알림을 실행합니다. 게임 빌드는 수동 시작 후 검사·보관·별도 알림이 자동입니다. 현재 기본 대상은 GameplayPreview, Build Settings는 SampleScene만 포함하고 개발 빌드로 고정돼 있습니다. 전체 게임 진입과 출시 빌드 구성은 후속입니다.

데이터 준비 실패와 준비 완료 소비자 오류는 구분합니다. 준비된 데이터는 유지하며 초기화 완료 소비자는 개별 오류를 기록합니다. 게임플레이 결과 이벤트는 동기로 전달하고 소비자 예외를 전역에서 격리하지 않습니다. 표시 소비자는 자기 표시 오류를 자기 경계에서 정리합니다. 사용자 저장 JSON의 버전/형식 확인은 배포된 콘텐츠의 중복 검사와 다른 책임입니다.

최초 자동 로딩 전환과 도구 변경은 DataSheet 소스·EXE와 클라이언트 코드를 함께 공유합니다. 후속 순서는 [남은 작업](Docs/남은%20구현과%20검증%20작업.md)을 따릅니다.
