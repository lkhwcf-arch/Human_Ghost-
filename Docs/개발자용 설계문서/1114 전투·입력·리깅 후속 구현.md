## 1. 전투 완료 순서

일반몹의 패링 성공 통지를 공격 정리 전 발행하면, 연출·구독자가 이전 공격 상태를 관찰하거나 예외로 정리가 끊길 수 있었습니다. 실제 충돌 경로는 성공 판단→일반몹 공격·돌진 정리/보스 체세 피해→성공 통지 순서입니다. 완료 통지에서 코어 명령을 다시 호출하지 않는 기존 계약을 유지합니다. 보스에게 새 패링 경직을 추가하지 않습니다.

~~~mermaid
sequenceDiagram
    participant H as 충돌 소유자
    participant P as PlayerActor
    participant E as 적 상태
    participant V as 연출 소비자
    H->>P: 패링 접촉 판단(통지 보류)
    H->>E: 공격 정리 또는 보스 체세 반영
    H->>P: 패링 완료
    P-->>V: 성공한 최종 상태 통지
~~~

## 2. 처형 보상과 저장

MonsterRewards가 기존 기본 보상과 ExecutionRewardSession의 추가 보상을 같은 지갑 변경에서 확정합니다. 확인할 수 없는 아이템 지급은 성공으로 기록하지 않습니다. 현재 공급값의 DropItemID는 0입니다.

~~~mermaid
flowchart LR
    A[실제 처형 완료] --> B[사망 보상 대기열]
    B --> C[조립자의 다음 처리]
    C --> D[보상·지갑 검증]
    D --> E[재화·EXP·처치 이력·추가 보상 이력·회복 확정]
    E --> F[완료 통지·연출]
    D --> G[실패는 저장하지 않음]
~~~

HealthChanged 안에서 보상 명령을 호출하지 않습니다. GameplayPreview.Saves는 사망 대상을 대기열에 넣고 처형 양쪽 정리가 끝난 뒤 FlushMonsterRewards에서 지급합니다. 저장 직전에도 대기열을 처리합니다. 지급 실패 시 그 상태로 저장하지 않고 기존 저장을 보존합니다.

SaveSnapshot.Executions에 오염과 스폰별 지급 이력을 보관합니다. 이전 v1 저장에 이 항목이 없으면 읽을 때 0·빈 이력으로 해석하며 파일을 임의로 다시 쓰지 않습니다. 저장 복원과 사망 시 마지막 저장의 처치·처형 이력을 함께 되돌립니다. 저장 후 재등장한 몬스터가 영구적으로 추가 보상을 잃지 않게 합니다.

MonsterPoiseView는 개체 머리 위 체세 표시만 소유합니다. 전투값·상태를 바꾸지 않고 전달된 런타임·몸체만 읽습니다. 실제 수치는 MonsterActor가 소유합니다. 복귀 시 HP는 유지하고 체세만 채웁니다.

## 3. 인식·이동·입력

MonsterAwareness는 MonsterAggro 정의와 정수 거리·높이·스폰 거리·시간을 받는 순수 코어입니다. MonsterActor가 공격·노출·처형 보호 상태와 복귀를 조정하고, PreviewMonsterDriver가 관측·원점 방향·실제 이동을 공급합니다. 매 프레임 장면 전체 검색을 추가하지 않습니다. 시트 수치를 다시 상수화하지 않습니다. 막힌 경로를 순간이동으로 우회하지 않으며 실제 맵 수용 확인이 남습니다.

HangAuto=Y일 때 PreviewPlayerMotion.Move가 공중 접촉 뒤 TryGrab을 호출합니다. 놓은 턱을 제외하고 탐색하며, 그 턱의 잡기 범위를 벗어나야 제외가 풀립니다. 수동 잡기 안내는 자동 모드에서 숨깁니다.

입력 에셋과 KeyboardControls의 재지정을 모두 F로 변경했습니다. 기존 E 포함 그림은 표시하지 않고 F 글자를 사용합니다. 전용 그림은 PlayerInteractor의 선택 연결점에 공급할 수 있습니다. 패드 위 방향 입력은 유지합니다.

약초 상태 가로 속도는 0입니다. 서낭당은 화면 동안 기존 앉기 클립의 앉은 자세를 유지하고, 닫기 후 앞 0.6초를 역재생합니다. 모달 잠금이 해제돼 시간은 흐르지만 별도의 일어서기 입력 잠금은 동작 끝까지 유지합니다. 저장 파일 쓰기가 늦게 끝나도 닫힌 화면의 앉기를 다시 시작하지 않습니다.

PreviewFollowCamera는 착지 높이를 유지해 일반 점프를 따라 위아래로 흔들리지 않게 합니다. 긴 낙하에서 화면 아래로 사라지지 않는 예외가 있고, 지상에서 위아래 0.5초 입력 후 3타일을 봅니다. 구도 수치는 Inspector에서 조정하며 실제 빌드 화면 확인이 남습니다.

## 4. UI 언어

LanguageTextSource.ReadUi가 UI_Lang.ID → TextID → Language.KO/EN을 공통으로 조회합니다. 화면별 번역 사전·복제 데이터·검사기를 추가하지 않습니다. UI 키·참조 검사는 기존 데이터 배포 검사를 사용합니다. 기능 고유 대사·팝업 문구의 Language ID 계약은 유지합니다.

연결 화면: 타이틀, 옵션, 일시정지·조작법, 새 게임 조작 선택, 서낭당, HUD, 저장 목록·수동 저장, 상호작용, 건너뛰기, 장부 반복 안내, 엔딩 마무리, 공용 오류 안내. LanguageSettings의 기존 변경 수명을 구독하고 해제합니다. 타이틀 메뉴는 KO 전용 그림 대신 텍스트로 번역을 표시합니다. 로고·배경은 유지합니다. 120개 데이터 행 중 현재 그려지지 않는 예약 기능까지 실제 화면 검증한 것은 아닙니다.

## 5. 리깅과 자산

지게귀는 기존 Idle 원본을 바탕으로 396정점·8뼈 스킨과 편집 가능한 달리기 클립을 만들었습니다. 네 개 이하 가중치를 정규화하고 부드러운 캡슐 영향 범위로 관절의 뒤집힘을 방지했습니다. 원본 PNG·원본 스프라이트 메타를 수정하지 않습니다. 새 리그 스프라이트는 Unity6 SpriteDataAccess로 생성하며 원본 임포터를 바꾸지 않습니다.

쇄문아비 2페이즈는 공급된 Test 부품 기반 기존 8뼈 리그를 사용합니다. BossPhaseTwoView.LeapTime이 실제 두 공중 구간 끝에 클립 1.2초 착지를 배치합니다. 별도 프레임 그림을 제작하지 않습니다.

Map_BossRoom_K9의 상단 발판 그림 묶음과 충돌체 12개만 비활성화했습니다. 지면·벽·마무리 관문과 StageExit 12행은 보존했습니다. 두 게임 장면의 기존 시험용 Instructions 객체를 비활성화했습니다. 원본 오브젝트·메타 GUID는 지우지 않았습니다.
