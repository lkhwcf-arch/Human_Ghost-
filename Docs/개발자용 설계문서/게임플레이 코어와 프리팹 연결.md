# 게임플레이 코어·프리팹 연결

> 2026-11-07 `769e205` 대조: 지상 4타·정수 이동·잠금 경계·상태와 표시 분리를 현재 코드에 맞췄습니다. 스프라이트 전투와 독립 리깅 시험본을 구분하며 최종 게임 연결과 실제 Play 수용은 별도입니다. 최신 상태는 [현황](현재%20구현과%20검증%20현황.md)을 따릅니다.

2026-11-03 최신 연결·개발 수치는 [기획 반영 기준](%EA%B8%B0%ED%9A%8D%20%ED%99%95%EC%A0%95%20%EB%B0%98%EC%98%81%20%EA%B8%B0%EC%A4%80.md)을 따릅니다. 두 테스트씬에 보스 설정과 HP Host 연결을 완료했습니다. 아래의 이전 검사 기록과 구분합니다.

내부 책임과 수정 위치는 [게임플레이 모듈 구조](%EA%B2%8C%EC%9E%84%ED%94%8C%EB%A0%88%EC%9D%B4%20%EB%AA%A8%EB%93%88%20%EA%B5%AC%EC%A1%B0.md)를 참고합니다. 기존 Actor 진입점과 프리팹 참조를 재사용합니다. PlayerRuntime.EnableSkill은 ContentAccess를 함께 받으며 PlayerRuntime·MonsterRuntime·BossRuntime은 SpatialRuntime의 위치 계약을 상속합니다.

표의 네 항목은 게임 전체로는 진행 상태입니다. 코어 검증을 실제 장치·물리·카메라 플레이 완료로 보지 않습니다. 일반 몬스터 체세·해체는 데모 범위 밖입니다.

표의 남은 연결은 운영용 기능 기준입니다. GameplayPreview에는 이미 임시 이동·접지·구르기·공격 범위·상호작용·텍스트 표시가 연결돼 있으므로 이 부분까지 미구현으로 해석하지 않습니다. 허수귀·지게귀 AI와 구속·돌진은 별도 일반 몬스터 문서의 구현 범위입니다.

## 기획 수치 수정

- 공격 시작값 원본: [전투 R2 C02](https://docs.google.com/document/d/1Rb3cszutAFQ7jgRUUXLay5NroVIJaHlV/edit). 조작: [코어 R2 K03](https://docs.google.com/document/d/1HL1SX7PY3UCCTe6RToyM1wDOfcObx68w/edit).
- `Assets/2.Model/Prefabs/Config/PlayerCombatSettings.asset`을 Inspector에서 편집합니다. 배열은 지상1·2·3·4타, 공중1타 순서입니다. Windup/Active/Recovery/ComboWindow는 ms, ExtraDamage는 ATK에 더하는 정수, PoiseDamage와 StaminaCost도 정수입니다. 공중 추가 피해 -2를 허용합니다.
- 초기값: `120/80/250/200/0/10/12`를 지상 1~3타에서 사용하고, 지상4타는 `200/100/400/0/+10/20/12`, 공중1타는 `100/80/200/0/-2/10/12`입니다. 실제 설정 에셋을 최종 기준으로 확인합니다. 값 결정·튜닝은 기획 담당입니다. 변경은 다음 런타임 초기화 때 반영됩니다. 실행 중 스냅샷을 임의 교체하지 않습니다.
- HP·이동·스태미나·구르기·피격 시간은 제공 `Player` 정의, 보스 HP/체세는 `Boss`, 회복/노출/해체 피해는 선택한 `BossState`에서 읽습니다. 해당 값은 DataSheet에서 수정·공식 배포합니다. 제공 생성 클래스·Bootstrapper는 수정하지 않습니다.
- 버선칼 보정은 현재 UnitStat에 이미 포함됐으므로 다시 더하지 않습니다. 공격 비용12를 자원 코어에 별도 고정하지 않습니다. `InputBuffer`와 콤보 창은 별개입니다.

## 프리팹·초기화

- `Assets/2.Model/Prefabs/MOP/PlayerGameplay.prefab`: `PlayerRuntime` + `PlayerLocomotionInput`. 전투 설정과 Move/Jump/Attack/Roll 참조를 연결했습니다. `BossGameplay.prefab`에는 `BossRuntime`을 둡니다. 렌더러·충돌체·좌표·앵커는 다른 담당이 연결할 위치입니다.
- 제공 `GameDataInitializer`의 초기화가 끝나면 완료 소비자가 `playerRuntime.Initialize(catalog, currentStamina, grounded)`를 호출합니다. `currentStamina`와 최초 접지는 호출자가 실제 초기 정책/관측으로 명시합니다. 호출 전에는 게임 입력이 전달되지 않습니다. 초기화는 한 번만 가능합니다.
- 이미 초기화된 `GameDataInitializer.Data`도 확인하고 완료 이벤트 구독은 비활성화 때 해제합니다. 이 프리팹은 데이터 공급자/저장소를 새로 만들거나 씬을 자동 검색하지 않습니다.
- 보스는 `bossRuntime.Initialize(catalog)`로 설정한 보스 ID·단계를 조회합니다. 기본 ID는 현재 데이터의1006, 단계는0입니다. 현재 BossState는 2행(4001 Phase0·HP100%, 4002 Phase1·HP50%)입니다. Inspector 단계는 시작 행입니다. 피해·해체로 HP가 뒤 행의 HPThreshold 이하(HP × 10000 ≤ 기준 × 최대 HP, 420이면 210 이하)가 되면 `BossPoise.Phase`가 그 행으로 바뀌고 `PhaseChanged(BossState)`가 같은 호출의 `Changed`보다 먼저 한 번 알립니다. 되돌아가지 않으며 사망 타격은 전환하지 않고, 여러 기준을 한 번에 넘으면 마지막 행으로 갑니다. 진행 중인 패턴·노출 시간은 끊지 않고 다음 대기·체세 회복·새 노출·다음 해체부터 새 행 값을 씁니다(해체 피해는 시작한 페이즈 값). 진행 중 패턴·노출을 유지하는 정책은 2026-11-03 개발 기준으로 채택했습니다. 포효 연출·전환 중 무적/정지는 아직 없습니다.
- 문 돌진(Skill1, C09): `BossPattern`의 `MinPhase`(1 = HP 50% 이하)보다 이른 페이즈에서는 `TryStart`가 거부합니다. 예비 동작 뒤 판정 창 동안 `BossCombat.Velocity`(= `Facing` × `ChargeSpeed`, tile_x100/초)를 어댑터가 이동에 적용합니다. 방향은 `Face(-1/1)`로 공급하며 패턴 중에는 고정됩니다. 판정 시간은 돌진 상한이고, 어댑터가 `NotifyWallHit()`를 호출하면 돌진을 끝내 후딜로 넘기고 체세를 `WallPoiseDamage`(C09 30)만큼 깎습니다. 체세가 0이 되면 노출이 패턴을 정리합니다. 2026-11-03 개발 기준으로 BossPatterns.asset에 속도1200·판정 상한2500ms·후딜800ms를 설정하고 BossGameplay에 연결했습니다. 테스트씬 PreviewBossDriver가 이동·벽·접촉을 전달하며 운영 물리 어댑터와는 구분합니다. 판정 창 열림 콜백 안에서 벽 충돌로 노출되어도 끝난 패턴을 진행하지 않습니다.
- 생성 후 `PlayerRuntime.Actor`/`BossRuntime.Actor`에서 현재 값을 읽고 `Initialized` 이벤트로 소비자를 연결합니다. 런타임 컴포넌트는 프레임의 소수 ms를 보존해 정수 Tick을 전달합니다. 순수 코어는 시간·입력·파일을 직접 읽지 않습니다.

## 입력·이동 경계

- 기존 `Assets/10.Input/InputSystem_Actions.inputactions`를 복제해 사용합니다. KeyboardControls가 설정에 따라 방향키 A 또는 WASD B만 활성화합니다. A는 점프 C·공격 X·구르기 Space·스킬 Z·약초 Q, B는 점프 K·공격 J·구르기 L·스킬 U·약초 I입니다. 상호작용은 두 방식 모두 E입니다. 입력 어댑터·바인딩은 현재 에셋과 키 배치 설정을 기준으로 하며 실제 패드 장치 검증은 미실행입니다. 기존 Crouch Action은 실제 구르기 코어 연결을 위해 같은 ID의 Roll로 정리했습니다. UI 맵과 다른 Action은 보존했습니다. 스킬·약초·상호작용·일시정지는 현재 추가 구현돼 테스트 씬에 연결됐습니다.
- 입력 어댑터는 원본 ActionAsset을 개체별 복제합니다. 자신이 소유한 복제본의 Action만 켜고 끄며 원본/다른 어댑터를 비활성화하지 않습니다. 두 입력 소유자에 같은 장치를 연결하면 같은 장치 명령이 둘에 전달되므로 단일 플레이어 프리팹에는 입력 어댑터 하나만 둡니다. 복제 수명 독립과 장치 페어링은 별개입니다.
- Move의 처리된 x 부호를 -1/0/1로 전달하고 취소·해제 시0을 전달합니다. 데이터 기반 행동 잠금 중에는 방향을 기억하되 실제 이동 요청 속도는0입니다. Jump 한 번 누르기는 한 번 승인되며 공중 재점프를 거부합니다.
- `JumpAccepted`와 `RollRequested(direction, distance, duration)`는 실제 물리 실행을 담당할 연결 신호입니다. 속도는 tile_x100/초, 거리/높이는 tile_x100 원본 단위입니다. 그리드 한 칸1을 프레임별 좌표 절삭/강제 스냅으로 해석하지 않습니다.
- 접지 센서는 새 실제 관측을 `PlayerRuntime.SetGrounded`로 전달합니다. 점프 승인 전의 오래된 grounded=true를 재전달하지 않습니다. 현재 PreviewPlayerMotion은 IntegerMotion의 정수 이동을 Unity 충돌 조회에 연결합니다. Rigidbody 기반의 별도 운영 어댑터를 새로 구현한 것은 아닙니다.

## 현재 제외한 기능

- 게임패드 실제 조작·장치분리·버튼 아이콘 검증은 후속입니다. UI와 게임 입력 소유권을 분리하고 현재 InputAction 에셋을 기준으로 연결합니다.
- [코어 기획서](https://docs.google.com/document/d/1PeoUGJMcHBdtNZ3iUfkn0FfzWJG3fou2/edit)의 Item 메모(전체 시스템 보류, 모션만 사용)와 추가 무기 메모(보류)에 따라 장착·인벤토리·StatJson 스탯 합성·추가 무기/무기 전환은 현재 구현·작업 범위에서 제외합니다. 지스타는 시작 무기 버선칼만 사용하며 쇠메는 보류합니다.
- 일반 버프·디버프·지속 회복은 지스타 미구현 범위입니다. 약초의 즉시 회복은 별도 기획 범위이며 일반 버프 시스템으로 확장하지 않습니다.
- 제공 Item/Buff 정의·데이터 테이블·생성 로딩 계획은 공급 계층의 계약입니다. 게임 기능을 제외하기 위해 공급 코드를 삭제하지 않습니다. 버선칼 수치는 기존 UnitStat에 포함된 값을 소비합니다.

## 컷씬 피해 차단 연결 (K16 R2)

수락한 연출 소유자 한 곳이 `player.SetCutsceneDamageBlocked(true)`를 호출하고, 완료·스킵·취소·실패·비활성 정리 때 자기 실행 흐름에서 false로 해제합니다. 거부된 중복 요청이 진행 중 연출의 차단을 해제하면 안 됩니다. 표시 이벤트 콜백 안에서 코어 명령을 다시 호출하지 않습니다. 입력·시간·소리 잠금은 별도 조립 계약입니다.

차단 중 직접 HP 피해·잡기/구속을 받지 않으며 타격 판정자는 기존 IsInvulnerable 경계에서 회피/치명 난수 전에 거부합니다. 해제는 구르기·피격·해체 무적을 제거하지 않습니다. 이 API와 검사는 완료했으나 실제 컷씬 표시/연출 조립은 후속입니다.

## 전투·해체 연결

- `PlayerActor.TryAttack`으로 시작/선입력을 요청하고 `CurrentAttack`·`IsAttackActive`·`AttackStarted`·`AttackWindowChanged`를 애니/히트박스에 연결합니다. 다음 타 비용은 실제 다음 타 진입 때 소모합니다. 후딜 시작 후 콤보 창을 지난 입력은 거부하며, 공중/4타 뒤에는 콤보가 없습니다. 지상1~3타 후딜은 구르기 캔슬,4타는 종료까지 캔슬 금지입니다. 공격 설정/AttackStarted 인덱스는 지상0~3·공중4이며 공중 상태 키는 Attack1을 유지합니다. PlayerCombatSettings는 필수5개, 체세8/8/8/16·공중8, 소모12씩입니다. 이전4개 설정은 초기화 오류로 거부합니다.
- 충돌 판정자는 양의 개체 식별자와 대상, 공격자 런타임의 `HitRandom`을 `TryHitBoss(targetId, boss.Actor, player.HitRandom)`에 전달합니다. 같은 형태로 `TryHitMonster`, 일반몹의 `TryHitPlayer`, 보스의 `BossCombat.TryHitPlayer`가 있습니다. Unity InstanceID는 음수일 수 있으므로 그대로 넣지 않습니다. 고정 ID를 여러 대상에 재사용하지 않습니다.
- 확률 타격 순서: 비판정·사망·무적·중복 대상 거부(난수 0회) → 창당 대상 한 번 등록 → 대상 Dodge 판정 → 회피 실패일 때만 공격자 Crit 판정 → 정수 방어/치명 피해와 체세 피해. 확률은 0~10000 정수(10000 = 100%), 난수는 `random(0, 10000)`으로 받는 0 이상 10000 미만 정수이며 `난수 < 확률`이면 성공합니다. 난수 10000은 공급 오류로 거부하며 보정하거나 다시 뽑지 않습니다. 결과는 `HitOutcome`(None/Dodged/Hit/Critical)입니다. 회피한 대상도 그 창의 등록은 소비하므로 같은 창에서 다시 추첨하지 않습니다. 잡기는 회피만 판정합니다. 범위 밖 확률·난수는 피해 적용 전에 거부합니다.
- 판정 어댑터는 매 프레임 확인과 함께 `AttackWindowChanged(true)` 순간에도 접촉을 한 번 확인합니다. 큰 프레임에서는 창이 한 Tick 안에 열렸다 닫힐 수 있어서, 프레임 확인만으로는 타격이 빠집니다. 이벤트 구독은 비활성화 때 해제합니다.
- 게임플레이 이벤트(`HealthChanged`·`AttackWindowChanged`·상태 `Changed` 등)는 호출 흐름 안에서 동기로 실행되며 소비자 예외를 격리하지 않습니다. 예를 들어 `HealthChanged` 소비자가 예외를 던지면 `ReceiveHit`의 반환과 공격자 쪽 후속 처리가 끊깁니다. 표시 소비자는 자기 표시 오류를 자기 경계에서 기록·정리하고 콜백 안에서 코어 명령을 다시 호출하지 않습니다. 데이터 준비 통지의 소비자 격리는 데이터 초기화 계층에만 적용됩니다.
- 타격 난수는 개체별 런타임이 소유하며 일반몹·보스의 패턴/대기 난수와 분리합니다. 기존 `(…, dodged, critical)` bool 호출은 검사·제어용으로 유지합니다. 해체 피해에는 회피·치명 판정을 넣지 않습니다.

## 보스 기본 패턴

- `BossCombat`은 BossPoise와 같은 상태 머신을 쓰며 패턴 실행·판정 창·패턴 간 대기(BossState IdleMin~IdleMax)만 소유합니다. HP·체세·노출·해체는 계속 BossPoise 소유입니다. `BossRuntime`이 같은 ms를 `Actor.Tick` → `Combat.Tick` 순서로 한 번씩 공급합니다.
- 패턴 선택은 외부 요청 `BossRuntime.TryStartPattern(index)`입니다. 코어는 외부 요청을 받고 PreviewBossDriver가 거리·상태에 따라 패턴을 선택합니다. HP 비율 페이즈 수치 전환은 BossPoise가 합니다(위 보스 절). 실행 중·대기 중·사망·노출·해체 중, 패턴의 `MinPhase`보다 이른 페이즈에서는 거부합니다.
- `BossPattern`은 타격마다 AttackSpec 하나를 순서대로 실행합니다. 2연타는 판정 창 두 개이며, 창마다 같은 대상을 한 번씩 허용합니다. 둘째 타의 Windup이 첫 타 뒤 간격입니다. 둘째 창에서 플레이어가 피격 무적이면 피해와 난수 없이 거부합니다.
- 사망·노출·해체가 되면 같은 호출 안에서 진행 중인 창과 대기를 정리합니다. 이후 Tick이 Dead/Exposed/Execute를 덮어쓰지 않습니다. 비활성화 시 `Release`로 정리합니다.
- 설정은 `BossPatternSettings`(인귀/보스 패턴 설정) 에셋입니다. 기획 제안 시작값은 내려찍기(Attack1) 선딜 700ms·추가 피해 +6, 휘두르기(Attack2) 예비 동작 500ms·추가 피해 0의 2회입니다. 2026-11-03 개발 기준으로 판정·후딜·2연타 간격은 BossPatterns.asset에, 임시 범위2.5/3.5타일은 테스트씬에 연결했습니다. 판정 시간이 0인 설정은 초기화 때 누락 오류로 거부합니다. BossRuntime에 설정을 연결하지 않으면 체세 기능만 동작하고, 패턴 요청은 누락 오류를 냅니다.
- `TryRoll`은 선딜/판정 중 거부, 후딜에는 공격을 취소합니다. 부족하면 상태/자원이 바뀌지 않습니다. `ReceiveHit(finalDamage, critical)`는 외부에서 확정한 HP 피해를 받으며 피격 시점부터 제공 HitIFrame을 적용합니다. Dead가 되면 행동/자원 진행을 멈춥니다.
- 보스 HP0이 체세0보다 우선합니다. 체세0이면 Exposed, 노출 기회를 놓치면 최대 체세로 복구합니다. `TryExecute(boss.Actor, inRange)`는 실제 범위 조건을 호출자가 전달하며 일반 몬스터를 받지 않습니다.
- 해체 중 플레이어/보스 무적, 타이머만으로 자동 종료하지 않습니다. 연출 종료 시 `CompleteExecution(restorePoise)`를 한 번 호출합니다. 피해는 최대HP×ExecuteDamage/10000, 나머지는 버림입니다(420HP·1800→75). 해체 후 체세 회복 여부는 회의 결과에 따라 호출자가 명시하며 기본값으로 확정하지 않습니다.
- HP/체세/스태미나 UI는 변경 이벤트 구독 + 현재 값 조회 + 비활성화 때 해제를 사용합니다. 이벤트를 물리 명령과 혼동하지 않습니다.
