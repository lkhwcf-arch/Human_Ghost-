# 발판 내려가기와 사다리 이동 설계

2026-11-09. 조작과 자산은 [사용 안내](../기획자용%20안내문서/하단%20점프·사다리·신규%20인게임%20UI%20확인%20안내.md)를 따릅니다. 상태 정의/CSV/JSON을 추가하지 않고 기존 런타임·공급 영역을 소비합니다.

- PlayerLocomotionInput은 아래+점프에서 TryDropThrough를 우선 호출합니다. GameplayPreview가 PreviewPlayerMotion의 함수를 연결하고 비활성 때 해제합니다. 빠졌던 이 연결을 보완했습니다.
- PreviewCollision은 현재 지지하는 일방 Collider와 DropThroughPlatform 허용 여부를 검사합니다. 그 Collider만 FindFloor에서 제외하고 몸이 아래로 지나면 제외를 끝냅니다. 일반 지면/비허용 발판/모달 입력 계약은 유지합니다.
- LadderClimbArea는 Map_ME의 기존 BoxCollider2D 트리거·속도를 제공합니다. PreviewPlayerMotion은 호출자가 준 Markers 묶음에서만 영역을 수집합니다. 전역 씬 탐색·데이터 위치 변경은 없습니다.
- 진입은 공간 관측을 공중으로 바꾸고 기존 Hang 상태로 전투/구르기를 막습니다. 사다리 안에서만 중력을 보류하고 중심선에 맞춰 정수 위치를 갱신합니다. 입력0은 위치 유지, 위/아래는 속도의 부호만 바꿉니다.
- 상/하단과 점프·피격·영역 제거·씬 종료에서 연결을 해제하고 기존 접지/공중 상태로 돌아갑니다. 위 끝에 중앙 지면이 없으면 양옆의 지지면을 확인합니다. 제거된 Unity 객체와 먼저 제거된 플레이어도 해제 경로에서 처리합니다.
- GameplayPreview가 연속 VerticalDirection을 전달하고 사다리 진입을 ↑ 상호작용보다 먼저 판단합니다. 대화/모달 입력 잠금은 수직 입력도0으로 만듭니다. 아래+점프 이탈은 낙하/발판 내려가기이고 일반 점프는 위로 이탈합니다.
- Climb 상태 ID를 임의로 추가하지 않습니다. PlayerRuntime.PresentationCue의 LadderUp/Down/Hold/Exit를 표시 소비자가 활성 수명에 구독합니다. PreviewPlayerSprite는 전용 루프를 선택하고 시간 부호/정지만 바꿉니다. 표시에서 코어 명령을 호출하지 않습니다.
- 새 UI는 기존 네 프리팹을 교체했습니다. HealthDisplay.SetFillRatio는 Filled 이미지의 fillAmount를 갱신하고 이전 사각형은 anchorMax 방식을 유지합니다. HudScreen도 같은 표시 경계를 사용합니다. 데이터 크기·HP·잔상 규칙은 그대로입니다.
- 실제 실행 맵은 기존 K9입니다. Map_ME 영역27개/동일 허용 발판7종에 컴포넌트만 붙였고 StageContentSet·스폰·운영 이동 데이터는 변경하지 않았습니다.

## 절벽 매달리기·기어오르기 보완 — 2026-11-10

매달리기 진입 시 모서리를 향하고, Hang 중 좌우 입력은 다음 이동 방향만 보관합니다. 코어의 방향·수평 이동과 표시 프레임은 고정합니다. 절벽 Hang에서는 표시 경과시간이 흘러도 첫 프레임을 유지합니다. 사다리는 별도 플래그가 있어 기존 위/아래/정지 루프를 유지합니다.

`PreviewPlayerMotion`이 기어오르기680ms의 시간·위치를 소유합니다. 기존 즉시 좌표 이동을 제거하고 처음70% 동안 위로, 40%부터 끝까지 발판 안쪽으로 이동합니다. 두 구간은 겹치고 각각 SmoothStep으로 양 끝을 감속해 꺾임 없이 이어집니다. 표시 크기·높이 보정도 같은 감속을 쓰며, 클립 프레임은 선형 진행률로 샘플링합니다. 끝까지 기존 Hang 상태로 이동·전투를 잠급니다. `PlayerRuntime.ClimbProgress`로 표시 진행률만 명시적으로 전달하고 `PreviewPlayerSprite`가 Climb 클립을 같은 비율로 샘플링합니다. 표시가 코어 명령을 호출하지 않습니다. 새 상태 등록은 하지 않습니다.680ms는 현재 개발 설정값입니다.

매달리기 지점은 각 맵 프리팹 `Markers` 아래의 `Hang_*` 빈 Transform 앵커입니다. `PreviewStage.Markers`를 통해 `PreviewHangEdges`로 전달됩니다. 2026-11-11 점검에서 K9 맵 6개(맵1 Hang_X62_P4·Hang_X68_P4, 맵2 Hang_X55_P4·Hang_X62_P4, 맵3 Hang_X52_P7·Hang_X104_P6)는 해당 Ground_N 프리팹 절벽 위 모서리와 오차 0으로 일치했습니다. 앵커는 Ground 프리팹의 자식이 아닌 좌표로 맞춘 표식이므로, Ground를 옮기거나 바꾸면 앵커도 함께 옮겨야 합니다. 공중 발판과 보스방에는 매달리기 앵커가 없습니다.

완료하면 접지·입력·보관된 방향을 복구합니다. 피격·사망·모서리 제거·비활성화는 중간 좌표에서 진행률/표시를 정리하고 공중/피격 상태로 돌아가며 발판 위로 강제 이동하지 않습니다. 위/점프의 중복 요청은 추가 이동을 만들지 않습니다. Unity 격리 검사에서 좌우 진입/고정, 반쯤 진행한 위치·프레임, 정상 종료·피격 취소, 사다리 표시 유지를 확인했습니다.

## 사다리 기능·표시 안정화 — 2026-11-10 후속

Map_ME7프리팹의27개 기존 LadderClimbArea를 실제 복제해 진입·상승·정지·하강을 확인했습니다. 별도 충돌 장면5경로에서 상단 인접 발판·하단·점프·피격·영역 제거를 검증했습니다. 합계182건 통과. 절벽의 매달리기 고정과 사다리의 수직 이동은 별도 분기입니다. 운영 맵 등록/스폰/관문은 수정하지 않았습니다.

`Player_LadderClimb.anim`은 완전한 Climb 프레임6·7·8·9·8·7,0.6초 폐루프입니다. 역방향은 현재 경과시간을 초기화하지 않고 재생 방향만 바꿉니다. 정지는0배율로 현재 자세를 유지합니다. 방향 전환 시 루프 끝에서 처음 자세로 급히 점프하던 연결을 없앴습니다.

모달/잠금 해제 프레임 뒤 PlayerLocomotionInput.Update는 가로 방향과 함께 계속 누르는 수직값도 복구합니다. 새 상호작용 이벤트는 재발행하지 않습니다. 플레이어 그림은 Idle 기준으로 최초1회 발을 맞추고 기본 상대 위치를 보존하며 실제 이동 뒤에 표시합니다. 절벽 매달리기만 손 기준 확대·아래 보정을 적용하고 사다리는 기존 기본 위치·배율을 유지합니다. 기어오르기 진행률·사다리 신호의 기존 책임은 유지합니다. 실제 키/패드 입력 수용은 Play에서 추가 확인합니다.

## 현재 실행 발판과 착지 복구 — 2026-11-11

[K18add R3](https://drive.google.com/file/d/1undlbdTUrRKZ1CRBiXt9uxopxnSobmDd/view)의 발판별 허용 표를 유지합니다. Air_Platform_3/4/5/7/8/10/12의7종은 아래+점프로 통과하고1/2/6/9/11/13의6종은 통과하지 않습니다. 실제 활성 인스턴스로13종을 확인했습니다. 해당6프리팹의 기존 금지 연결을 유지합니다. 기존 Map_ME7종·고정 Ground·명시 금지 정책과 스폰/맵 JSON은 유지합니다. 2026-11-11 사용자 확정으로 도화골(8001)의 Air_Platform_1/2도 허용합니다(K18 금지표와 다름). 금지는 6/9/11/13입니다.

일반 공중 상태에서 아래+점프를 미리 누르면 기존 점프 버퍼 안에서 허용 발판을 통과합니다. 공격·구르기·매달림·피격·패링·사망 등 행동 잠금 중 하단 점프는 예약하지 않습니다. 공중공격 착지는 잔여 공격을 정리해 이동을 복구하는 별도 경계이며 공격 중 발판 통과를 허용하는 특례가 아닙니다. 지지 Collider만 제외하고 몸이 통과한 뒤 복구합니다. 허용7/금지6·고정/명시 금지 차단·일반 공중 예약·공중공격 착지 직후 이동을 격리 검증했습니다.

## Editor 이동과 카메라 확인 — 2026-11-11

Unity Play에서 인귀 → 테스트 → 장부방 입구로 이동 / 보스방 입구로 이동을 사용합니다. 기존 GoToStage/LoadingScreen/저장 준비 수명을 사용하며 준비 전·로딩·사망·저장·대화·모달·일시정지 중에는 메뉴를 비활성화합니다. 장부방8005 Spawn_FromDohwagol, 보스방8004 Spawn_FromHyeopgok에 도착합니다. 진행 해금·보상·보스 부활을 조작하지 않습니다. 테스트 이동 진입 코드는 UNITY_EDITOR에만 포함합니다.

PreviewFollowCamera는 바라보는 방향으로0.8타일 앞, 대상보다2.8타일 위를 목표로 합니다. 기존 SmoothDamp·맵 가장자리/좁은 맵 제한·최저 높이를 유지합니다. 공격/패링 방향 잠금을 따르고 장부방을 제외한 전 맵의 투영 크기는 기획 수정 컨펌에 따라4.3이며 보스방도 고정 대신 같은 추적 구도를 씁니다. 장부방3.6은 유지합니다. 실제 Play 두 메뉴 도착과 로딩 완료를 확인했으며 검사용 저장 폴더를 사용해 기존 사용자 저장 기록은 변경하지 않았습니다.

## 메인 카메라 시작 구도 일치 — 2026-11-11 후속

사용자 요청으로 MapDohwagolTest의 MainCamera 태그를 가진 PreviewCamera 시작 Transform Y를1.8→4, 편집용 최저 높이를4, Camera의 Orthographic Size를5.625→4.3으로 맞췄습니다. 맵 진입 때 사용하는 StageContentSet의8001~8004 크기4.3과 장부방3.6은 이미 최신 작업에 반영돼 있어 유지했습니다. 추적은 기존 대상 높이2.8/앞0.8·맵 경계·테스트 배율을 사용합니다. 시작 Y=4는 화면 높이 고정 명령이 아니며 추적 중에는 캐릭터 높이에 따라 변합니다.

구도 참조: [Hollow Knight 공식 플레이 화면](https://www.hollowknight.com/), [Blasphemous 공식 플레이 화면](https://www.team17.com/games/blasphemous). 현재 투영 크기는 최초5.625 대비 약31% 확대입니다. 카메라 저장값·각 맵 크기 소비·테스트 배율1.25→실제 크기3.44·기존 배율 복원을 격리 확인했습니다.

## 신규 사다리 표시 — 2026-11-11

PlayerClimb의 완전한 교대 주기10프레임을 전용 루프로 연결했습니다. 상승/하강/정지는 기존 신호를 쓰고 절벽의 매달리기·오르기와 분리합니다. 공통 셀·피벗을 사용하며 사다리에서는 기본 표시 배율을 유지합니다. 실제 그림자도 같은 렌더러를 읽습니다. 세부 프레임과 검증은 [애니메이션 연결 설계](캐릭터%20상태%20애니메이션%20연결%20설계.md#player_skill_finalplayerclimb-연결--2026-11-11)를 봅니다. 맵 등록·스폰·사다리 물리 속도는 이번에 바꾸지 않았습니다.
