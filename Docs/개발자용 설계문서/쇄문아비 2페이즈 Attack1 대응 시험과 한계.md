## 기준 자료

- `Assets/4.Sprite/Swaemoon/attack1.png`의 `attack1_00`~`attack1_12`: 실제 BossGameplay 프리팹의 Attack1 원화 13장입니다. 00번도 정상 그림입니다.
- `Assets/2.Model/Prefabs/Config/BossPatterns.asset`의 Attack1(10004): 준비 700ms, 타격 120ms, 회복 600ms, 총 1420ms. 2페이즈에서도 이 타이밍을 사용합니다.
- `PreviewBossSprite.GetFrame`은 공격 전체 시간에 원화를 균등 배치합니다. 각 장의 구간은 약 109.23ms입니다. 700~820ms의 타격 구간은 06~07번에 걸칩니다. GIF의 13×130ms=1690ms를 게임 기준으로 사용하지 않았습니다.
- C09 쇄문아비 R2의 Attack1은 문짝 내려찍기입니다. [확인한 팀 기획서 사본](https://docs.google.com/document/d/15j7ZZTBYxbZs1k9qZVZwjvxkO1gUrRxL/edit)을 참고했습니다. 기획서와 기존 공격부를 새롭게 해석하거나 전투 수치를 바꾸지 않았습니다.

별도 공격 프리팹이나 새 리그를 만들지 않고 사용자가 수용한 `Prefabs/Swaemunabi_Phase2_WalkRig.prefab`을 씬 인스턴스로 재사용했습니다. Root, Body, 양쪽 UpperArm/Forearm/Hand의 8뼈 이름·계층·바인드 포즈·정점·가중치·원본 픽셀을 변경하지 않았습니다. 새 뼈도 없습니다.

Animation 창에서 Body 위치 XYZ·회전 Z와 팔 6뼈 회전 Z를 편집할 수 있습니다. Root 변위, 뼈 스케일, 피해 이벤트, 충돌이나 게임 전이 변경은 없습니다. 팔 길이를 유지하는 두 관절 계산을 사전에 키로 변환했으며 런타임 IK 또는 뼈를 흔드는 반복 스크립트가 아닙니다.

원화의 팔 들기 → 접기 → 앞으로 내려치기 → 복귀 순서에 맞춰 **육안 기반으로 근사한 키 포즈**를 배치했습니다. 정확한 관절 추적 데이터나 원화 복제 결과는 아닙니다. 특히 04~05번은 가려진 면과 단축 투영이 있어 손목 위치를 확정할 수 없습니다. 이 구간의 오른팔 표시 순서를 뒤로 보내는 시험 키를 넣었지만 원화의 입체적 회전과 같은 결과가 되지는 않습니다. 옷·몸통 실루엣도 한 장을 변형하므로 동일하게 복제되지 않습니다.

Attack1에서 처음 사용하는 Body 회전이 기존 상태에 남지 않도록 **새 시험 컨트롤러의 모든 상태에서 Write Defaults를 일관되게 사용**했습니다. 원래 컨트롤러는 수정하지 않았습니다. 시험 스크립트가 공격 진입을 Play로, 복귀를 0.18초 CrossFade로 실행합니다. 실제 보스 전투 전이에 이를 연결하는 것은 별도 작업입니다.

두 원본은 모두 100 PPU, 배율 2.3으로 비교하고 바닥선을 맞췄습니다. 1페이즈 pivot y=0과 2페이즈 pivot y=24 차이로 원화 부모 y에 -0.552를 적용했습니다. 1페이즈 기존 Bilinear/압축과 2페이즈 Point/비압축 설정은 보존했으므로 화면의 선명도도 다릅니다.

## 실제 Play 결과

최종 클립 보정 뒤 실제 Play를 다시 실행했습니다. 좌우 각각 3회, 총 6회 공격과 Idle·Walk 복귀를 확인했습니다. Walk는 2유닛/초로 부모를 이동시키고 공격 중에는 그 위치를 유지합니다. 카메라만 함께 이동해 비교를 유지하며, 좌우 독립 시험을 바꿀 때 위치를 초기화합니다. 공격 포즈는 편집 가능한 클립에서 재생했습니다.

뒤집힘 횟수는 여러 표본에서 같은 삼각형을 반복 검사한 관측 수입니다. 전체 픽셀 수나 고유 손상 삼각형 수가 아닙니다. 접지는 공격 중 전환을 제외한 지지 **손 뼈** 기준이며 손바닥 모든 픽셀의 접지를 검증했다는 뜻이 아닙니다. 복귀 검사는 전환 종료 후 기존 클립의 곡선과 뼈를 비교했습니다. 임의 게임 컨트롤러나 실제 피해 타이밍의 통합 검증은 하지 않았습니다.

오른쪽 타격 화면은 클립 0.71138초/원화06, 왼쪽 타격 화면은 0.77674초/원화07로, 실제 0.70~0.82초 구간입니다. 접힌 준비 자세와 타격 화면을 실제 이미지로 확인했습니다. 원화에 가까운 앞으로 뻗는 방향을 적용하면 기존 가중치의 어깨·오른팔 변형이 커지는 문제가 남습니다. 팔을 수직으로 제한해 수치만 낮추면 원화 공격에서 멀어지므로 완성으로 표시하지 않았습니다.

콘솔 컴파일 오류는 0개였습니다. 기존 시험에서도 보였던 `Deleting invalid font reference.` 경고 1개가 재생·종료 과정에 나타났습니다. Play를 종료하고 비교 씬을 열어 두었습니다.

## 보존 및 후속 판단

Attack1 시작 전 캐릭터 폴더의 기존 파일 81개를 SHA-256으로 비교해 변경 0개를 확인했습니다. 승인된 Idle·Walk 클립, 리그, 컨트롤러, 시험 씬, 과거 검증 파일과 원본은 보존했습니다. 공용 게임 씬·보스 코드·전투 설정·원화 임포트 설정은 수정하지 않았습니다. 브랜치·커밋·푸시는 하지 않았습니다.

기술적인 후속 후보는 공격 전용 사본의 어깨·팔 메시와 가중치를 조정해 현재 클립의 접힘을 없애는 것입니다. 이는 새 공격 설계와는 구분됩니다. 다만 원화 04~05의 몸통 회전과 가려지는 팔, 06~08의 옷자락 면 변화는 가중치만으로 보장할 수 없습니다. 그 모습까지 동일하게 요구한다면 2페이즈의 가려진 면과 부위 분리 원화가 필요하며 팀의 시각 기준 확인이 선행돼야 합니다. 현재 근사 포즈를 팀 결정으로 확정하거나 기존 리그를 덮어쓰지 않았습니다.
