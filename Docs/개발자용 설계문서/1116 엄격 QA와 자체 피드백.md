## 4. 깐깐한 게이머 관점의 자체 피드백

1. **불공정한 턱 선공은 기능적으로 막았지만, 설명 없이 무적이면 규칙을 오해할 수 있습니다.** 추가 HUD를 남발하기보다 턱에 몸을 올리는 시각 동작과 실제 보호 종료가 맞는지 새 관람자로 확인해야 합니다. 무적은 턱 이동에 한정하며 사다리에는 주지 않았습니다.
2. **두 막대는 오해를 줄일 기반이며 최종 가독성 디자인은 아닙니다.** 작은 적이 여럿 겹칠 때 흰 체세와 붉은HP가 구별되는지, 노출 뒤 체세가 복구되는 이유를 읽는지는 별도 체감 지표입니다. 테두리·바탕 최종 아트를 공급받아야 합니다.
3. **시작 안내는 조작표를 배경에 펼친 단계입니다.**9개 동작이 보이지만 플레이어가 실제 성공했는지 단계별로 확인하는 튜토리얼은 아닙니다. Z의 기능 설명30368+와 팻말 아트가 오면 문장/배치를 다듬어야 합니다. 지금 임시 검은 받침은 배경 미술을 가립니다.
4. **카메라가 넓어져도 낙사 비용의 불만까지 없어지지는 않습니다.** 이번 확정은 즉사·서낭당 복귀 유지입니다. 상하250ms 대기와 아래6칸 보기는 위험을 읽게 돕지만, 초심자가 아래 보기를 자발적으로 쓰는지 측정해야 합니다. 정책을 몰래 HP20 복귀로 바꾸지 않았습니다.
5. **보스 판정 숫자가 맞는 것과 공격이 읽히는 것은 다릅니다.** 범위 일치 검사는 통과했지만 사슬·파동·불가 패링 표시는 최종 연출 아트와 함께 평가해야 합니다. 보스가 화면 밖에서도 전투를 지속하므로 카메라가 보스를 놓쳤을 때 공격 예고가 충분한지도 후속 관찰 항목입니다.
6. **소리가 연결됐다는 사실을 청취 합격으로 쓰지 않습니다.** 패링 음원·출력 경로는 확인했습니다. 실제 전시장 음량/BGM 속 구별, 헤드폰/스피커 차이는 실기 청취가 필요합니다.
7. **실패한 시험 자체도 분리했습니다.** 동일 프레임 입력 방지에 걸린 UI 자동 시험과 비활성 사다리를 잡으려던 시험은 시험 준비 오류를 수정해 다시 실행했습니다. 제품 결함 수에 더하지 않았습니다. 강제 위치 배치와 정상 플레이 경로도 구분합니다.

## 5. 추가한 시험 기능

기존 **F8 보스 시험창**에 **피드백 QA 진단 갱신 / QA 진단 기록 복사**를 추가했습니다. 에디터와 개발 빌드 전용이며 정식 빌드에는 없습니다.

- 플레이어: 현재 상태·접지·매달림·턱 보호·무적, HP·약초 현재/최대.
- 적별: HP·체세·어그로·같은 바닥·플레이어/적 화면 포함 여부·보행 구간.
- 맵·보스 추적·카메라 크기·혼·엽전.

진단은 읽기만 하며 재화·HP·AI·입력을 바꾸지 않습니다. 갱신 버튼 시점에 기록하고 복사하므로 새 전역 검색/상시 기록·네트워크 전송은 없습니다. 기존 보스 처치/바로 이동 기능은 진행을 바꾸므로 시험 저장에서 사용합니다.

재현 추천: 아래층에서 위층 적을 화면에 넣기→점프→턱 매달림→오르기→완전 접지→화면 이탈. 각 지점에서 진단 기록을 남기면 인식 시작/해제 원인을 비교할 수 있습니다.

## 6. 검증 한계와 다음 재시험

이번 기록은 실제 Unity 런타임·원본 자산·UI 이벤트/렌더를 이용한 자동/통제 검사입니다. 사람이 키보드/패드로 전 루트를 몇 시간 완주한 결과로 주장하지 않습니다. 물리F는 이전 사용자 확인 기록이 있으며 이번 새 하드웨어 조작/청취를 대신하지 않습니다.

남은 공급은 [통합 사용자 작업 목록](1115%20유저테스트%20기획%20반영%20현황과%20사용자%20작업%20목록.md#2-사용자에게-남는-작업)을 따릅니다. 장시간 실행·여러 해상도/패드 전수·전시장 청취·전체 갈림길 반복 플레이는 별도 수용 범위입니다. 개발용 수동 저장 UI의 중복 EventSystem 경고 이력은 기존 개발 도구 범위이며 별도 기록합니다. 경고를 지워 정상이라고 보고하지 않습니다.
