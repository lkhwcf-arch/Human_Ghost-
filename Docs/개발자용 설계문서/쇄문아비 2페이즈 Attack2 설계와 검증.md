`Assets/2.Model/Prefabs/MOP/BossGameplay.prefab`의 `PreviewBossSprite._clips`에서 Attack2(10005)의 실제 참조를 읽었습니다. 순서는 `Assets/4.Sprite/Swaemoon/attack2.png`의 00~12 다음 `attack5.png`의 00~12, 총 26장입니다. 두 시트의 첫 칸도 정상 원화이며 투명한 빈 프레임이 아닙니다.

`BossPatterns.asset`의 첫 타격은 준비 500 / 활성 100 / 회복 0ms, 다음 타격은 준비 250 / 활성 100 / 회복 600ms입니다. 총 1550ms, 활성 구간은 500~600ms 및 850~950ms입니다. `PreviewBossSprite.GetFrame`은 공격 전체 시간에 모든 원화를 균등 배치합니다. 각 원화 길이는 약 59.615ms, 두 번째 시트 시작은 775ms입니다.

이번 클립은 현재 구현의 원화 순서와 재생 시간을 그대로 기준으로 삼았습니다. 오른팔을 들어 준비하고 몸 앞으로 횡으로 휘두르고 복귀하는 확인 가능한 키 포즈를 기존 2페이즈 체형에 맞춰 근사 배치했습니다. 가려진 준비 자세를 새로운 팀 디자인으로 확정하지 않았습니다.

| 새 파일: Assets/5.Animation/Swaemunabi_Phase2/ 아래 | 역할 |
| --- | --- |
| `Clips/Swaemunabi_Phase2_Attack2_Study.anim` | 편집 가능한 1.55초 비루프 클립, 30fps 표시, Transform 10곡선×313키 및 RightArm 표시 순서 1곡선 |
| `Controllers/Swaemunabi_Phase2_Attack2_Study.controller` | 새 비교용 Idle / Walk / Attack1 / Attack2 상태, 기존 클립 참조 |
| `Scenes/Swaemunabi_Phase2_Attack2_Study.unity` | 왼쪽 2페이즈, 오른쪽 실제 프리팹에서 읽은 26장 원화 비교 |
| `Preview/SwaemunabiAttack2Preview.cs` | 원화 동기화, 이동·반전·재진입·전환과 한글 표시 |
| `Validation/attack2_*` | 실제 Play 캡처 14장, 수치, 키 포즈와 사전 검사 자료 |

기존에 수용한 `Prefabs/Swaemunabi_Phase2_AttackRig.prefab`을 변경 없이 재사용했습니다. 메시·가중치·텍스처·8뼈 이름·계층·바인드 포즈 변경이 없습니다. 오른팔은 원화 키 포즈에 대응하는 위팔·전완 회전을 보간하고, 지지 왼손은 몸통 이동에 맞춘 관절 계산을 키로 구웠습니다. 손목 길이·뼈 스케일은 유지하며 Root 이동과 런타임 IK는 없습니다. 시작과 끝은 기존 2페이즈 기본 포즈입니다.

준비 구간 원화 04~07에 해당하는 RightArm 표시 순서를 뒤로 보냈습니다. 이는 평면 리그의 가림 근사이며 몸통의 입체적 회전을 재현한 것은 아닙니다. .anim이 뼈 움직임을 담당하며 테스트 스크립트만으로 동작을 만든 것이 아닙니다.

새 비교 컨트롤러만 모든 상태에 Write Defaults를 일관되게 사용합니다. 공격 진입과 Attack2 연속 재진입은 Play, Idle·Walk 복귀는 0.18초 CrossFade로 확인했습니다. 기존 게임의 상태 전이·피해·전투 설정에는 연결하거나 수정하지 않았습니다.

## 현재 원화와 판정 시점의 차이

| 시점 | 현재 원화 |
| --- | --- |
| 약 0.477초 | attack2_08, 첫 큰 횡 휘두르기 잔상 |
| 0.50~0.60초 | 첫 활성 구간, 주로 attack2_08~09 및 끝의 10 일부 |
| 0.775초 | attack5_00 시작 |
| 0.85~0.95초 | 두 번째 활성 구간, attack5_01~02 |
| 약 0.954초 | attack5_03의 큰 횡 휘두르기 |
| 약 1.312초 | attack5_09의 주황색 이펙트가 있는 휘두르기 |

따라서 현재 게임에서는 두 번째 활성 구간과 뒤쪽 원화의 큰 휘두르기가 일치하지 않습니다. 이번 작업에서 판정에 맞춰 원화를 재배열하거나 동작 시간을 임의로 당기지 않았습니다. 기존 연계의 어떤 시각 동작을 두 번째 판정으로 볼지는 팀 확인이 필요한 부분입니다. 비교 화면에 현재 판정 구간과 원화 이름을 표시했습니다.

## 실제 Play 검증

좌우 각각 Attack2 네 번, 총 여덟 번을 재생했습니다. Attack2 → Attack2 연속 재진입과 Idle·Walk·Attack1 사이 진입/복귀를 포함했습니다. Attack1도 좌우 한 번씩, 총 두 번 실제 재생했습니다. 모든 Attack2 실행에서 회복 끝 프레임까지 확인했습니다.

| 상태 | 표본 | 삼각형 검사 | 뒤집힘 | 모든 변 최대 길이 비율 |
| --- | ---: | ---: | ---: | ---: |
| Attack2 | 323 | 11,153,836 | 0 | 1.39516747 |
| Attack1 | 73 | 2,520,836 | 0 | 1.450385 |
| Idle | 133 | 4,592,756 | 0 | 1.06780279 |
| Walk | 259 | 8,943,788 | 0 | 1.74631119 |
| 전환 중 | 37 | 1,277,684 | 0 | 1.65617383 |

Attack2 부위별 최대 비율은 Body 1.13040268, LeftArm 1.39516747, RightArm 1.00004053입니다. 지지 왼손 뼈의 최대 이동은 0.000145277 원본 픽셀, Root 로컬 변위와 공격 중 부모 변위는 모두 0입니다. 복귀 포즈는 428표본에서 기존 클립 곡선과 비교했으며 회전 오차 0.0000611도, 위치 오차 0.000012 원본 픽셀 이하였습니다. Body 회전과 RightArm 표시 순서도 초기값으로 복원됐습니다.

관절 겹침 사전 검사는 Attack2 105표본에서 어깨·팔꿈치 두 부품이 함께 덮는 격자점이 최소 126개 / 252개였습니다. 기존과 같은 반경 25픽셀, 간격 1픽셀 검사이며 실제 화면 검증과 구분합니다. 접지는 손 뼈 기준입니다. 모든 실루엣 픽셀 또는 원화와의 동일성을 보장하는 수치가 아닙니다.

실제 화면에서 좌우의 횡으로 뻗은 팔, 준비 자세, 뒤쪽 휘두르기, 복귀를 확인했습니다. 오른쪽 첫 판정 캡처는 0.51165초/attack2_08, 두 번째 판정 캡처는 0.88375초/attack5_01, 늦은 휘두르기 캡처는 1.34257초/attack5_09입니다. 왼쪽에서도 대응 장면을 캡처했습니다. 전체 값은 `Validation/attack2_play_metrics.json`에 있습니다.

## 보존과 남은 차이

Attack2 시작 전 캐릭터 파일 149개를 SHA-256으로 비교해 기존 파일 변경 0개를 확인했습니다. 승인된 Idle·Walk·Attack1, 공격 프리팹과 소스, 모든 이전 비교 씬·컨트롤러·검증 자료를 보존했습니다. 공용 원본, 게임 씬, 보스 로직, 전투 설정을 수정하지 않았습니다. 브랜치·커밋·푸시도 하지 않았습니다.

원화는 몸통이 돌아가며 보이는 면을 바꾸고 긴 잔상과 주황색 이펙트를 포함합니다. 현재 평면 8뼈 리그에는 그 면과 효과 그림이 없으므로 새로운 픽셀이나 무기 디자인을 추가하지 않았습니다. 준비 구간에서 2페이즈 팔이 원화보다 더 보이며, 체형·옷자락·관절 겹침의 윤곽 차이가 남습니다. 도트 변형은 지지 왼팔에서 최대 약 1.40배입니다. 원화와 완전히 동일한 최종 결과로 승인된 것은 아니며, 결과의 `meshDeformationPassed`와 `visualMatchApproved`를 분리했습니다.

컴파일 오류는 없었습니다. 스크립트 갱신 중 MCP WebSocket 재연결 경고가 한 차례 있었으나 연결이 복구돼 전체 검증을 마쳤고, 마지막 Play 검사 시 Console 오류·경고는 0개였습니다. Play를 종료하고 새 비교 씬을 저장된 상태로 열어 두었습니다.
