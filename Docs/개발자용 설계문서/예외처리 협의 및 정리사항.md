## 용어: 알림 처리 실패

**이 문서의 "알림 처리 실패"는 UI 알림 표시 실패나 이벤트 구독 실패가 아닙니다. 이벤트를 발행(`Invoke`)했을 때 구독해 둔 처리 함수 안에서 예외가 나는 경우입니다.** 구독은 정상으로 연결되어 있고, 호출되는 순간 받는 쪽 코드가 실패하는 상황입니다.

### 구조는 분리돼 있어도 실행은 한 흐름

기능끼리 서로를 직접 참조하지 않는다는 점에서 각 기능은 독립적입니다. 그러나 C# 이벤트는 동기 호출이라, 실행될 때는 모든 구독자가 발행자의 호출 흐름 안에서 등록 순서대로 실행됩니다. 아래는 P0·10의 실제 경로입니다.

```text
FlushMonsterRewards()
 └ MonsterRewards.TryGrant()
    └ CurrencyWallet.TryApply()
       ├ commit()                 ← 처치 기록·경험치·재화 확정(이미 완료)
       ├ Wallet.Changed.Invoke()
       │   ├ 첫 재화 안내 큐       ← 여기서 예외 발생 시
       │   ├ 서낭당 재화 표시      ← 뒤쪽 구독자 미실행
       │   └ 텔레메트리
       ├ LeveledUp.Invoke()       ← 미실행
       └ Granted.Invoke()         ← 미실행
 └ catch → _monsterRewardsFailed = true  ← 이후 보상·저장 잠금
```

구독자 하나가 예외를 던지면 다음 세 가지가 함께 일어납니다.

| 영향 | 내용 | 해당 항목 |
| --- | --- | --- |
| 뒤쪽 구독자 미실행 | 같은 이벤트에 나중에 등록된 처리 함수가 호출되지 않음 | P0·10 |
| 발행자 후속 코드 미실행 | `Invoke` 뒤에 있던 상태 정리 줄이 실행되지 않음 | P0·01, P0·02 |
| 호출자의 실패 판단 | 예외가 호출자까지 올라가 확정 완료된 결과를 실패로 처리 | P0·10 |

### 프로젝트 규칙과의 관계

동기 실행과 소비자 예외 비격리는 [AGENTS.md](<../../AGENTS.md>)의 책임 분리 규칙에 따른 의도된 설계입니다. 같은 규칙이 "표시 소비자는 자기 Unity 표시 오류를 자기 경계에서 기록·정리"하도록 정합니다. 따라서 이 문서의 지적은 이벤트 구조를 바꾸자는 것이 아니라, 규칙이 지켜지지 않았거나 순서가 어긋난 지점을 찾자는 것입니다.

| 확인 지점 | 문제 유형 | 현재 예 |
| --- | --- | --- |
| 발행자 순서 | 필수 상태 정리 전에 알림을 먼저 보냄 | `BossCombat.ClearPattern`, `PlayerActor.ClearAttack` |
| 표시 소비자 경계 | 자기 오류를 직접 기록·정리하지 않아 예외가 밖으로 나감 | 첫 재화 안내의 `Currency` 조회. 텔레메트리는 내부에서 잡음 |
| 호출자 판단 | 확정 후 알림만 실패한 경우를 확정 실패로 처리 | `_monsterRewardsFailed` |

### 실제 발생 조건

정상 플레이에서는 발생하지 않습니다. 버그나 데이터 문제가 생겼을 때 피해가 어디까지 번지는지를 정하는 문제입니다.

- 데이터 행 누락으로 `GetTable<>().Get(id)`가 예외를 던짐
- 씬 전환 중 이미 파괴된 UI 오브젝트 접근(`MissingReferenceException`)
- 프리팹 연결 누락으로 인한 null 참조

협의의 기준은 표시 하나의 오류가 전투 종료·보상·저장 같은 게임 상태를 막지 않게 하는 것입니다. 필수 연결 실패는 숨기지 않고 조립자에게 실패로 전달하는 기존 원칙은 유지합니다.

## 첫 검증 순서

1. **CI 원인 분리.** #315·#316의 실패 조건에 예상 파일 수, 실제 읽은 파일 수, 첫 파일명, 목록 차이를 출력해 같은 Windows CI 환경에서 확인합니다. 현재 반복 실패이며 로컬 재현은 되지 않았습니다.
2. **보스 사슬과 플레이어 피격.** 격리 코어 재현 2건을 첫 회의 안건으로 사용합니다. 정상 종료, 중간 취소, 중복 종료, 콜백 예외 때 HP·판정·구속의 최종 상태를 합의합니다(피격 시 경직·무적은 없음으로 확정). 같은 "확정 뒤 알림 실패" 원칙으로 P0·10 보상 잠금도 함께 다룹니다.
3. **필수 예고·씬 복구·저장 실패·일시정지 복귀(P1·11).** 실패 시 화면과 복귀 위치, 입력 해제 주체를 확정하고 격리 슬롯·대표 프리팹에서만 실패를 주입합니다.
4. **현장 체감.** 산길 새 첫 무리, 가마터 곡사, 턱/사다리 혼합 전투, 보스 사슬을 30/60/120fps와 한 번의 긴 프레임에서 비교합니다. 커밋·맵·공격 ID·이전/현재 위치와 판정 시간·종료 이유를 남깁니다. 실제 Unity 재현 및 빌드는 이번 협의 준비에서 미실행입니다.

전투 종료 순서는 전투 개발, 맵·씬 전환과 저장 복구는 각 모듈 담당, 공격 예고·허용 경계는 기획과 함께 확정할 항목입니다. 이번 확인은 원본 피드백과 두 저장소를 읽는 범위에서 진행했습니다.
