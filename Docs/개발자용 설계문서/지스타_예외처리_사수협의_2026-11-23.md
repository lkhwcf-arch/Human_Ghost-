| §8~9 적 AI·옹귀 / E06~E14 | 8방향 인식과 실제 공격 가능 여부를 분리. 상하층·벽·발판 끝에서 근접/돌진/투척 각각 선택 조건 결정. 곡사 1200ms의 마지막 100ms부터 피해가 열리는 구조이므로 실제 착지·그림자·피해 시각을 비교. 공격자 취소·죽음 때 돌의 수명, 벽 차단, 다수 적 동시 압박은 기획 결정. 비후퇴 쿨타임은 현 공급 0, 양수 사용 전 검증 또는 소비 지원 여부 결정. |
| §10·12~15 탐색·최적화·검수 / X03~X10, R10~R11 | 역방향 이동·사망·이어하기의 탈출 가능성, Alt+Tab 후 입력, 타이틀 왕복 때 참조·메모리 누적. 기획상 허용할 우회부터 결정. 리깅·아틀라스·BGM 변경의 화질·타격음·첫 프레임 지연은 동일 빌드와 조건의 비교로 판단. |

## 첫 검증 순서

1. **CI 원인 분리.** #315·#316의 실패 조건에 예상 파일 수, 실제 읽은 파일 수, 첫 파일명, 목록 차이를 출력해 같은 Windows CI 환경에서 확인합니다. 현재 반복 실패이며 로컬 재현은 되지 않았습니다.
2. **보스 사슬과 플레이어 피격.** 격리 코어 재현 2건을 첫 회의 안건으로 사용합니다. 정상 종료, 중간 취소, 중복 종료, 콜백 예외 때 HP·판정·구속·경직·무적의 최종 상태를 합의합니다.
3. **필수 예고·씬 복구·저장 실패.** 실패 시 화면과 복귀 위치, 입력 해제 주체를 확정하고 격리 슬롯·대표 프리팹에서만 실패를 주입합니다.
4. **현장 체감.** 산길 새 첫 무리, 가마터 곡사, 턱/사다리 혼합 전투, 보스 사슬을 30/60/120fps와 한 번의 긴 프레임에서 비교합니다. 커밋·맵·공격 ID·이전/현재 위치와 판정 시간·종료 이유를 남깁니다. 실제 Unity 재현 및 빌드는 이번 협의 준비에서 미실행입니다.

전투 종료 순서는 전투 개발, 맵·씬 전환과 저장 복구는 각 모듈 담당, 공격 예고·허용 경계는 기획과 함께 확정할 항목입니다. 이번 확인은 원본 피드백과 두 저장소를 읽는 범위에서 진행했습니다.
