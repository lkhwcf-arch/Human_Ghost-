# 쇄문아비 2페이즈 Walk 개선과 검증

2026-11-06, Unity 6000.2.8f1 / 2D Animation 12.0.2 / Coplay MCP for Unity 10.2.0. [사용 안내](../기획자용%20안내문서/쇄문아비%202페이즈%20Walk%20초안%20확인%20안내.md).

## 변경 범위

기존 리그를 덮어쓰지 않고 `Source/Boss_Phase_2_WalkRig.png`와 `Prefabs/Swaemunabi_Phase2_WalkRig.prefab` 사본을 만들었습니다. 경로 기준은 `Assets/5.Animation/Swaemunabi_Phase2/`입니다.

기존 Root, Body, UpperArm_L/R, Forearm_L/R, Hand_L/R의 8개 뼈 이름·계층·바인드 포즈를 유지했습니다. 세 Sprite의 뼈 데이터와 bind pose 행렬, 정점 위치와 삼각형 인덱스를 원본과 비교해 차이가 없음을 확인했습니다. 원본 이미지 픽셀도 보존했습니다. 변경한 것은 18,403개 정점의 가중치이며, 뼈 추가나 그림 수정은 없습니다.

초안은 팔 외곽과 손목에도 몸통 가중치가 남아 있어 큰 보행에서 메시를 접었습니다. 개선본은 실제 불투명 픽셀의 연결 그래프에 따라 몸통·상완·전완·손의 영역을 지정하고 관절 경계에서 가중치를 확산했습니다. 끈과 매듭은 위팔과 몸통 사이에서 연속적으로 연결했습니다. 가중치 경계의 기울기를 다듬고 왼쪽 손목은 넓은 전환 구간으로 조정해 국소 늘어남을 줄였습니다. 몸통·팔 간 공유 정점은 같은 가중치를 사용합니다.

`Clips/Swaemunabi_Phase2_Walk.anim`과 기존 Idle 클립은 변경하지 않았습니다. Walk는 1.3초, 30fps 표시, 120Hz 간격 157키, Body 위치 XYZ와 팔 6개 회전의 총 9곡선입니다. 루프 양끝 값·접선 차이는 0이며 Root 이동을 넣지 않았습니다.

시험은 `Scenes/Swaemunabi_Phase2_Walk_Refined_Test.unity`에서 기존 WalkPreview 컨트롤러를 덮어쓴 프리팹 인스턴스로 수행합니다. `Preview/SwaemunabiWalkPreview.cs`는 부모 이동·좌우 반전·상태 전환·측정만 담당합니다. 뼈 움직임은 .anim이 담당하며 런타임 IK는 없습니다. 표시 문구를 일반적인 테스트 문구로 바꾸고, Play 종료 시 동적 한글 폰트를 해제하도록 보완했습니다.

## 실제 Walk Play 검증

게임 참고값 MoveSpeed 200 및 PreviewBossDriver의 /100 변환, worldUnitsPerTile=1에 따라 초당 2유닛을 사용했습니다. BossGameplay.prefab의 배율은 2.3, 기존 Walk 13프레임/10fps는 1.3초입니다. 양손은 반 주기 차이, 60% 지지·40% 복귀이며 지지 중 로컬 이동은 부모 이동을 상쇄합니다. 원본 Swaemoon/walk.gif의 1.69초 타이밍과는 구분했습니다.

최종 가중치를 적용한 뒤 다시 실제 Play에서 측정하고 화면을 확인했습니다. 수치는 `Validation/walk_refined_play_metrics.json`에 있습니다.

| --- | --- |
| 오른쪽/왼쪽 Walk | 3.49462 / 3.49828주기 |
| Walk → Idle 복귀 | 2회 |
| 손 뼈 접지 비교 | 1,692회, 구간 최대 오차 0.000457원본 픽셀 이하 |
| 손 하단 고정 정점 | 65개, 2,772회 비교, 최대 오차 0.000446원본 픽셀 이하 |
| 메시 검사 | 86시점, 삼각형 2,894,932회 |
| 뒤집힘 관측 | 0회 |

| 모든 변 최대 비율 | 1.74625 |

접지 수치는 전환과 착지·이륙 경계를 제외한 위상 .025~.575에서 측정했습니다. 모든 전환 프레임의 접지가 완벽하다는 뜻은 아닙니다. 뒤집힘 관측 횟수는 여러 프레임의 반복 검사 수입니다. 초안과 비교한 3.23→1.43은 동일하게 삼각형의 첫 번째 변을 검사한 값이며, 개선본에서는 검사 범위를 넓혀 모든 변의 최대 1.75도 별도로 기록했습니다.

네 장의 `walk_refined_*.png`는 실제 Play 프레임입니다. 화면과 검사에서 기존 메시 접힘·손 형태의 심한 왜곡·연결부 벌어짐은 해소됐습니다. 관절 주변 도트가 늘어나는 현상은 남습니다. 1.75배 국소 늘어남을 포함하므로 픽셀 형태가 완전히 고정된 최종 원화 품질로 단정하지 않습니다.

## Idle 회귀

`Scenes/Swaemunabi_Phase2_Idle_Regression_Test.unity`는 왼쪽 개선본, 오른쪽 원래 리그에 같은 기존 Idle을 동시에 재생합니다. `Validation/idle_refined_play_metrics.json`에 실제 Play 측정을 기록했습니다.

## 보존 및 한계

Walk 이전부터 있던 캐릭터 파일 38개를 SHA-256으로 비교해 변경 0개를 확인했습니다. 이번 개선 전 파일 중 수정된 것은 시험 전용 `SwaemunabiWalkPreview.cs`뿐이며, 사본 자산·회귀 씬·검증 이미지와 JSON을 추가했습니다. 원래 Idle 클립·컨트롤러·테스트 씬·프리팹·원본 소스·이전 검증 파일을 보존했습니다. 공용 게임 씬·전투 코드·기존 전이는 수정하지 않았고 브랜치·커밋·푸시를 하지 않았습니다.

Play 종료 시 나타났던 동적 폰트 참조 경고는 시험 표시 코드의 해제로 보완했고 마지막 재생·종료 확인에서는 콘솔 오류·경고 0개였습니다. 최종적으로 Play는 종료하고 개선 Walk 테스트 씬을 열어 두었습니다.

원본 오른팔 말단은 왼손처럼 손가락이 펼쳐진 형태가 아닙니다. 그 실루엣을 보존했으며 가려진 신체나 새 손가락을 그리지 않았습니다. 큰 회전·다른 동작의 보이지 않던 면까지 해결한 것은 아닙니다. 정점 수가 많은 현재 메시의 게임 성능 최적화도 별도 과제입니다.

실제 게임의 PreviewBossSprite는 프레임 배열을 표시하며 새 Animator를 연결하지 않았습니다. 조사한 추적 이동 코드에서 Walk 상태 설정 경로도 확인되지 않아, 실제 보스 연결은 별도 구현·검증 작업입니다. `walk_draft_*.png`와 초안 테스트 씬은 이전 실패 사례 기록으로 남겼습니다.
