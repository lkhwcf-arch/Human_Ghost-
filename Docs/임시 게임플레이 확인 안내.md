# 임시 게임플레이 육안 확인

## 2026-11-03 갱신

- 두 테스트씬 모두 최신 Player/Boss/Monster 프리팹 연결과 기존 HP 표시 Host를 사용합니다. 보스가 추적하고 내려찍기·2연타를 순환하며 HP210 이하에서 문 돌진을 추가합니다. 테스트 이동 한계에 부딪히면 체세30 감소입니다. 사슬 패턴은 포함하지 않습니다.
- 도화골은 `Map_1_Dohwagol_R3c`로 교체했습니다. 이 씬의 몹·보스는 전투 검사 배치이며 ‘운영 도화골 몹0’ 기획을 바꾸지 않습니다.
- 플레이어 키는1.5타일. 몹은 허수귀 `Heosugui_Idle_0`·지게귀 `1.Idle_0` 한 장씩 고정합니다. 방향만 반전하고 공격·허점·사망 색을 보여 줍니다. 애니메이션은 없습니다. 몹 판정은 기존 사각형의 bounds를 그대로 사용합니다.
- 허수귀 잡기는 ATK−5 피해 + 최대1000ms 구속, X3회 조기 해제입니다. 보스·수치·기획 우선순위는 [기획 반영 기준](기획%20확정%20반영%20기준.md), 최신 검사 결과는 [검증 현황](현재%20구현과%20검증%20현황.md)을 따릅니다.
## 실행

Unity에서 `Assets/1.Scene/GameplayPreview.unity`를 열고 Play를 누른 뒤 Game 뷰를 클릭합니다. 장면에는 기존 PlayerGameplay·BossGameplay와 허수귀 HusugwiGameplay·지게귀 JigegwiGameplay 프리팹 인스턴스가 있습니다. 청록색은 플레이어, 빨간색은 보스, 초록색은 허수귀, 주황색은 지게귀입니다. 플레이어·보스·일반몹에 현재 상태·체력(·자원)을 표시합니다. 일반몹은 플레이어를 발견하면 추적·공격합니다. 일반몹 스프라이트가 밝은 빨간색이면 공격 판정 중, 보라색이면 지게귀 벽 충돌 허점입니다. 허수귀에게 잡히면 플레이어 이름표에 남은 공격 연타 횟수가 나옵니다(X/X 연타로 해제).

맵 위 배치 확인은 `Assets/1.Scene/MapDohwagolTest.unity`를 사용합니다. 같은 구성에 `Map_1_Dohwagol_R3c` 맵 프리팹을 놓고 플레이어를 PlayerStart에, 허수귀·지게귀·보스를 지면 위에 배치한 복사본입니다. 카메라는 고정이고 화면 이동 한계(±8)는 맵 x 2~18 구간입니다. 맵 충돌체 물리와 카메라 추적은 연결하지 않았습니다. 이 씬의 플레이어는 파란 사각형 대신 `Assets/4.Sprite/Player` 시트에서 상태마다 한 프레임을 보여줍니다(`PreviewPlayerSprite`, 애니메이션 없음). 대기 1.Idle_0, 이동 2.Walk_3, 점프 14. Jump_4, 착지 12.Land_0, 구르기 13.Roll_4, 공격 1·2·3타 5.Attack(1)_2·6.Attack(2)_3·5.Attack(1)_1, 피격 4.Hit_2, 치명 피격 8.CritHit_2, 구속 4.Hit_1, 해체 9.Execute_9, 사망 10.Dead_8을 씁니다. 원본은 왼쪽을 보므로 오른쪽으로 갈 때 좌우 반전합니다. 사각형은 렌더링만 끄고 판정 범위로 계속 사용합니다. 타격의 회피·치명은 실제 Dodge·Crit 확률로 판정합니다.

제공 GameDataAssets → GameDataInitializer → 기존 PlayerRuntime/BossRuntime 순으로 실제 배포 데이터를 소비합니다. CSV 파서·조회 저장소·Bootstrapper를 추가하지 않습니다. 이 장면의 초기 자원은 Preview 컴포넌트의 시작 시 스태미나 최대로로 명시하며, 끄면 시작 스태미나를 사용합니다. 운영 스폰 정책을 확정한 값은 아닙니다.

씬의 제목·조작 안내·상태·체력/스태미나/체세와 확인용 Inspector 표시는 한글로 제공합니다. Hierarchy 오브젝트·앵커·호출용 이름은 영문 ASCII를 사용합니다. 프로젝트의 기존 Pretendard-Regular 글꼴을 재사용합니다. 코드 식별자와 프리팹 파일명은 유지합니다.

## 조작

게임패드 작업은 보류하며 현재 확인 범위는 키보드 조작입니다.

| 입력 | 육안 확인 |
| --- | --- |
| 방향키 | 사각형 이동, 대기/이동 전환 |
| C | 점프 요청, 공중 재점프 거부, 착지 |
| X | 기존 지상 3타·공중 1타, 공격 중 자원 소모 |
| Space | 구르기 요청·거리·자원·무적 색상 |
| 보스 가까이에서 공격 | 노란 판정 사각형이 겹치면 기존 보스 피해·체세 API 호출 |
| H (확인 전용) | 보스 ATK/플레이어 DEF를 기존 피해 공식에 넣어 피격 요청 |
| E (확인 전용) | 가까운 급소 노출 보스에 기존 해체 시작 API 호출 |
| R (확인 전용) | 기존 해체 완료 API 호출. 체세 회복 여부는 Preview 설정에 명시 |

### 키 배치 시험 (B안)

Play 중 메뉴 `인귀/테스트/키 배치 B 켜기`를 누르면 WASD 이동은 그대로 두고 공격 X→J, 점프 C→K, 구르기 Space→L로 바꿉니다. 처형 E·확인용 H/R은 그대로입니다. `키 배치 B 끄기` 또는 Play 종료로 원래 배치로 돌아갑니다.

- `PreviewKeyLayout`은 입력 어댑터가 복제한 입력 에셋에만 런타임 바인딩 덮어쓰기를 적용합니다. 원본 `InputSystem_Actions.inputactions`·입력 어댑터·씬·프리팹은 수정하지 않습니다.
- 메뉴가 만드는 임시 오브젝트는 씬에 저장되지 않습니다. 규칙은 오브젝트 Inspector에서 바꿔 다른 배치(예: 점프 C→Space, 구르기 Space→L)도 시험할 수 있습니다.
- 화면 조작 안내 문구는 바뀌지 않습니다. 정식 키 배치는 기획 확정 후 입력 에셋에 반영합니다.

무적은 노란색, 공격 판정 중에는 주황색, 보스 노출은 보라색, 사망은 회색으로 표시합니다. HP/자원 값은 기존 런타임의 현재 값을 읽습니다. 다시 시작하려면 Play를 종료하고 재진입합니다.

## 임시 연결의 경계

- GameplayPreview는 초기화·구독/해제와 호출 순서를 조정합니다. PreviewPlayerMotion은 임시 이동, PreviewMonsterDriver는 개체별 관측·판정, PreviewPresentation은 텍스트·색상을 담당합니다. 일반 C# 내부 클래스이므로 씬/프리팹에 새 컴포넌트를 연결할 필요가 없습니다. [모듈별 책임](게임플레이%20모듈%20구조.md)을 따릅니다.

- GameplayPreview 컴포넌트는 이 장면에만 있습니다. 프리팹 루트의 기존 런타임·입력 참조와 GUID를 유지했습니다.
- 기존 두 프리팹에 임시 시각화/사각형와 임시 시각화/이름표만 추가했습니다. 사각형 SpriteRenderer의 bounds는 이 장면의 공격·피격 판정 입력이기도 합니다. 보이지 않게 하려면 렌더링만 끕니다(MapDohwagolTest의 플레이어 사각형이 이 방식). 대체 판정을 연결하기 전에 임시 시각화 그룹이나 사각형 객체·컴포넌트를 비활성화·삭제하면 판정이 멈추거나 참조 오류가 납니다.
- 이동은 수신한 tile_x100 값을 타일당 화면 거리로 변환해 Transform을 표시합니다. 점프는 제공 JumpHeight와 Inspector의 임시 점프 시간 (초)의 포물선입니다. 바닥·벽 충돌, Rigidbody·중력·경사·모서리/매달리기·정식 카메라는 구현하지 않습니다.
- 구르기 거리·시간은 제공 Player 값을 사용합니다. 화면 이동 한계 (좌우)는 화면 밖으로 나가지 않기 위한 이 확인 장면의 표시 제한입니다.
- 공격은 노란 SpriteRenderer의 bounds와 보스 사각형 bounds가 겹치는지만 보는 임시 범위 판정입니다. 판정 창이 열리는 순간과 매 프레임 확인합니다. 회피·치명은 공격자 런타임의 `HitRandom`으로 실제 Dodge·Crit 확률을 판정합니다(`HitOutcome` 오버로드). `dodged`·`critical` bool 오버로드는 검사·제어용입니다. 운영 히트박스·대상 선택을 대체하지 않습니다.
- E의 범위는 Preview의 임시 해체 거리 (타일), R의 체세 복구는 해체 확인 후 체세 회복에서 조정합니다. 연출 완료 신호와 운영 종료/페이즈 정책은 여전히 별도 결정입니다.
- 프레임 재생 애니메이션·정식 HUD 레이아웃은 이 장면에 포함하지 않습니다. 플레이어 상태별 단일 프레임·일반몹 고정 단일 프레임과 임시 HP 막대만 연결했습니다. 일반 몬스터 체세/해체는 활성화하지 않습니다. 허수귀·지게귀 AI는 MonsterActor가 실행합니다. 이 장면의 몬스터 이동(Transform)·중심 거리 관측·화면 좌우 한계를 벽으로 쓰는 판정은 확인용이며(근접·잡기는 사각형 높이가 겹칠 때만 명중, 점프로 피할 수 있음) 운영 물리·히트박스가 아닙니다. 몬스터 데이터 ID/표시 이름과 임시 시각화 자식은 각 프리팹에서 조정합니다.

## 확인 결과

아래 Play 검사는 이전 작업에서 기록된 결과이며, 이번 문서 점검에서는 재실행하지 않았습니다. 최신 기본 검사는 [현재 구현과 검증 현황](%ED%98%84%EC%9E%AC%20%EA%B5%AC%ED%98%84%EA%B3%BC%20%EA%B2%80%EC%A6%9D%20%ED%98%84%ED%99%A9.md)을 참고합니다.

실제 Unity Play에서 가상 키보드 → 기존 Input Actions → 런타임 Update → Preview LateUpdate 경로로 16개 항목을 확인했습니다. 이동/정지·점프/착지·구르기/거리·판정 창 1회 피해·지상 3타·피격·보스 노출/해체·명시적 완료·비활성화/재활성화·텍스트 값이 통과했습니다. 가상 장치와 검사 이벤트는 종료 후 제거했습니다. 실제 키보드 사용자 조작과 운영 물리는 별도 확인 대상입니다. 게임패드 개발·검증은 보류합니다.
