# 기획자용 K9 맵 공급과 연결 확인 안내

도화골의 지면 구간에서 새 가로 반복 이미지의 윗면이 캐릭터 발 위치와 맞고 구간을 따라 이어지는지 확인합니다.

도화골의 기존 불타는 초가와 일반 초가 배치에서 새 이미지가 표시되고 건물 바닥이 기존 위치에 맞는지 확인합니다.

도화골의 불타는마을 A/B 중경에서는 지붕선을 따라 불꽃이 반복됩니다. K9과 Map_ME에서 가로 반복 구간을 지나며 두 레이어의 불꽃과 배경이 함께 움직이는지 확인합니다.

도화골(8001)의 연기 기둥 세 곳은 불꽃과 연기가 반복 재생되는지 확인합니다. 01·02는 오른쪽으로, 03은 왼쪽으로 기울어집니다.

도화골(8001)에 진입해 기존 모닥불 위치에서 불꽃이 반복 재생되는지 확인합니다. Map_ME 도화골 프리팹은 별도로 열어 Play 모드에서 확인할 수 있습니다.

## 1. 현재 준비된 것

맵 1·2·3, 장부방, 보스방 K9 프리팹이 프로젝트에 들어왔습니다. 파일이 있는 것과 실제 게임에 연결된 것은 다릅니다. 현재 StageContentSet에는 8001~8007이 등록되어 있습니다. 8005는 Map_Jangbubang_K9와 배포된 Assets/Data/Json/spawn/8005.json을 참조합니다. 실제 플레이를 마쳤다는 뜻은 아닙니다.

```mermaid
flowchart LR
    A[기획·아트: K9 프리팹 공급] --> B[개발자: Stage ID·프리팹·스폰 원본 연결]
    B --> C[장부방·왕복 위치·관문 확인]
    C --> D[실제 빌드에서 왕복·사망·저장·완주]
```

## 2. 기획자가 전달할 것

1. 실제 사용할 맵 프리팹 이름과 Stage ID를 전달합니다. 새 파일이 생겼다고 임의 ID를 만들지 않습니다.
2. 시작·되돌아오는 위치·문·서낭당·관문 표식을 확인합니다. 이름은 영문 ASCII를 유지합니다.
3. 몬스터는 확정한 플랫폼 배치 JSON의 StageID·PlacementID·개체 순서를 유지합니다. 새 배치 순서로 바꾸면 기존 처치 기록의 의미가 달라질 수 있으므로 개발자와 먼저 협의합니다.
4. 8005도 DataSheet/spawn 원본에서 검사·배포합니다. 맵별 최대 수는 MaxMonsterCount, 실제 수량과 위치는 Monsters·MonsterCount·Points로 조정합니다. 클라이언트 배포 파일을 직접 수정하지 않습니다.

## 3. 개발자에게 요청할 최초 연결

8005 등록과 문 왕복 요청은 구현되어 있습니다. 필드의 연속 배치, 장부방 암전 왕복 방식, 별도 보스 씬은 추가 연결·수용 검증을 요청합니다. 현재는 같은 테스트 씬을 맵마다 다시 읽으며 빌드 목록에 별도 보스 씬이 없습니다. 표만 수정한다고 씬이나 프리팹 참조가 자동 생성되지는 않습니다. 새 씬 연결은 준비 완료 후 진행합니다.

도화골 배경의 생성 높이는 StageContentSet의 8001 항목에서 Background Positions의 Local Y로 조정합니다. Play에서 생성된 맵의 Background/Mountains 아래 먼산과 Fog_Far의 로컬 Y를 확인합니다.

## 4. 정상 결과 확인

- 몬스터를 남겨도 일반 출구를 이용할 수 있어야 합니다. 마을 장부 조건·기획 잠금은 별개입니다.
- 이전 맵으로 돌아왔을 때 처치 기록이 유지되는지, 사망하면 마지막 저장 이후 처치만 되돌아오는지 확인합니다.
- 장부방 입구·복귀·보스 입장·서낭당 위치에서 떠 있거나 원점에 생성되지 않는지 확인합니다.
- 새로운 공간의 실제 왕복은 아직 검증되지 않았습니다. 문제가 있으면 Stage ID·프리팹 이름·스폰 파일·이동 방향·첫 오류를 전달합니다.

관련 안내: [서낭당 저장](서낭당%20저장과%20몬스터%20처치%20기록%20확인%20안내.md), [컷씬과 씬 이동](기획자용%20컷씬%20표시와%20씬%20이동%20안내.md).

도화골 8001에서 기존 모닥불 자리의 불꽃이 9프레임으로 반복 재생되는지 Play에서 확인합니다.


## 출구를 데이터로 설정하기 — 2026-11-14

### 무엇을 수정하나요?

DataSheet의 `tables/Stage.xlsx`에서 **StageExit** 탭을 수정합니다. 한 행은 출발 공간에서 목적 공간으로 가는 출구 하나입니다. 역방향 행이 없으면 돌아갈 수 없는 편도입니다. 같은 출발 공간에 여러 행을 넣으면 여러 출구가 됩니다.

```mermaid
flowchart LR
    A[맵에 영문 앵커 배치] --> B[StageExit 한 행 입력]
    B --> C[DeployData 실행·검사 성공]
    C --> D[새 코드가 반영된 Unity에서 Play]
    D --> E[진입·도착·왕복 여부 확인]
```

### 각 칸의 뜻

| 칼럼 | 입력 방법 |
| --- | --- |
| ID | 다른 출구와 겹치지 않는 고정 정수 |
| StageID | 출발 Stage ID |
| TriggerType | LeftEdge 왼쪽 끝 / RightEdge 오른쪽 끝 / Area 앵커 주변 / Interact 문 상호작용 |
| AnchorName | Area·Interact에서 출발 맵 Markers의 앵커 이름. 양 끝은 빈칸 |
| TargetStageID | 목적 Stage ID |
| ArrivalAnchorName | 목적 맵 Markers의 도착 앵커 이름 |
| RangeX·RangeY | 타일×100 정수. Area는 가로·세로 반폭. 양 끝은 가로 여유만. Interact는 둘 다 0 |
| PromptTextID | Interact에서 사용할 Language ID. 다른 방식은 0 가능 |
| BlockedTextID | 잠금 안내 Language ID. 표시하지 않으면 0 |
| ContentEnabled | Y 사용 / N 사용 안 함 |
| Note | 작업 메모. 게임에 공급하지 않음 |

예를 들어 Area의 RangeX 160·RangeY 200은 앵커를 중심으로 좌우 1.6타일·위아래 2타일인 영역입니다. Interact의 거리는 공통 상호작용 설정을 사용합니다.

### 현재 공급 예시와 새 갈림길 작성

현재 공급 행에는 `8007 / Area / Exit_ToHyeopgok / 8003 / Spawn_FromGalimgil` 연결이 있습니다. 갈림길의 해당 영역에 들어가면 협곡의 지정 지점으로 갑니다. 협곡에서 돌아오는 연결은 별도 행입니다.

새 출구는 다음 순서로 작성합니다.

1. 출발 맵의 Markers 아래 빈 오브젝트를 만들고 영문 이름을 붙입니다. 예: Exit_ToCave. 원하는 위치로 옮깁니다.
2. 목적 맵 Markers에도 도착용 빈 오브젝트를 만듭니다. 예: Spawn_FromFork.
3. 새 ID의 행에 실제 출발·목적 Stage ID와 두 앵커 이름을 입력합니다. 위 이름은 설명용 예시이므로 실제 공급된 리소스로 바꿉니다.
4. 자동 이동은 Area와 범위, 버튼으로 이동할 문은 Interact와 PromptTextID를 입력합니다.
5. 편도라면 역방향 행을 만들지 않습니다. 왕복이면 반대 방향의 별도 행을 만듭니다.
6. DeployData 검사 후 Unity에서 진입·도착과 입력 복귀를 확인합니다. 기존 실행파일은 다시 빌드해야 바뀝니다.

### 주의와 확인

- 현재 출발 앵커는 맵 Markers 기준입니다. 생성된 플랫폼 안의 앵커·움직이는 출구 연결은 아직 지원하지 않습니다.
- 같은 맵에 출구를 여러 개 만들 수 있지만 자동 진입 영역을 겹치지 않게 둡니다.
- 목적지 콘텐츠가 잠겨 있으면 해당 출구로 이동하지 않습니다. 막힌 목적지를 건너뛰어 다른 맵으로 보내지 않습니다.
- 도착 위치가 출구와 겹치면 바로 되돌아가지 않습니다. 영역 밖으로 나간 뒤 다시 들어와야 합니다.
- 검사 성공 후에도 실제 앵커가 Markers 안에 있는지, 발판 위에 착지하는지, 편도·왕복 의도대로인지 Play로 확인합니다.
- 오류가 나면 출구 ID·출발/목적 Stage ID·앵커 이름·첫 오류를 개발자에게 전달합니다. 원점으로 대체하거나 메타 파일을 삭제하지 않습니다.

### 에디터 테스트 이동 확인

장부방·보스방으로 바로 이동하는 기존 에디터 테스트 기능도 StageExit의 도착 앵커를 사용합니다. 별도 Inspector 필드 할당은 필요하지 않습니다. 같은 목적지에 서로 다른 도착 앵커를 여러 개 설정하면 이 간편 이동은 하나를 임의로 고르지 않습니다. 그 경우 일반 출구에서 이동을 확인하고, 특정 도착 지점의 직접 시험은 개발자에게 요청합니다.

### 장부방에서 나온 뒤 산길 진입 재확인

출구 범위의 데이터 단위 변환을 수정했습니다. RangeX 160은 그대로 1.6타일이므로 시트 값을 크게 늘릴 필요가 없습니다. 새 코드 반영 후 장부 조사를 마치고 도화골로 나와 오른쪽 출구로 이동해 산길 진입을 확인합니다. 장부 조사 전 산길 잠금은 유지됩니다. 실행파일은 다시 빌드해야 수정이 적용됩니다.

### 장부방 완료 후 사망 복귀

장부 조사를 마친 뒤 초기 구간에서 사망하면 장부방을 다시 진행하지 않고 산길 시작점으로 복귀하도록 기존 예외를 연결했습니다. 복귀 공간은 Stage의 마을 NextStage를 사용합니다. 별도 필드 할당은 필요하지 않습니다. 이후 공간의 서낭당을 활성화했다면 그 복귀 지점이 유지됩니다. 새 게임이나 수동 저장 불러오기의 위치를 바꾸는 기능은 아닙니다.

확인 순서: 장부 조사 전 사망 → 기존 시작점 / 조사 완료 후 초기 구간 사망 → 산길 시작점 / 후반 서낭당 활성화 후 사망 → 해당 서낭당. 실제 Play로 세 경우를 확인합니다.
