# 기획자용 K9 맵 공급과 연결 확인 안내

## 1. 현재 준비된 것

맵 1·2·3, 장부방, 보스방 K9 프리팹이 프로젝트에 들어왔습니다. 파일이 있는 것과 실제 게임에 연결된 것은 다릅니다. 현재 StageContentSet에는 8001~8005가 등록되어 있습니다. 8005는 Map_Jangbubang_K9와 Map_ME/spawn/L8005_Jangbubang.json을 직접 참조합니다. 실제 플레이를 마쳤다는 뜻은 아닙니다.

```mermaid
flowchart LR
    A[기획·아트: K9 프리팹 공급] --> B[개발자: Stage ID·프리팹·스폰 원본 연결]
    B --> C[장부방·왕복 위치·관문 확인]
    C --> D[실제 빌드에서 왕복·사망·저장·완주]
```

## 2. 기획자가 전달할 것

1. 실제 사용할 맵 프리팹 이름과 Stage ID를 전달합니다. 새 파일이 생겼다고 임의 ID를 만들지 않습니다.
2. 시작·되돌아오는 위치·문·서낭당·관문 표식을 확인합니다. 이름은 영문 ASCII를 유지합니다.
3. 몬스터는 확정한 플랫폼 배치 JSON의 StageID·PlacementID·개체 순서를 유지합니다. 새 배치 순서로 바꾸면 기존 처치 기록의 의미가 달라질 수 있으므로 개발자와 먼저 협의합니다.
4. 클라이언트 spawn/8005.json은 있지만 DataSheet 원본에는 아직 없습니다. 배포 도구로 재현 가능한 원본 공급 위치를 담당자와 맞춥니다. 클라이언트 배포 파일만 고치고 끝내지 않습니다.

## 3. 개발자에게 요청할 최초 연결

8005 등록과 문 왕복 요청은 구현되어 있습니다. 필드의 연속 배치, 장부방 암전 왕복 방식, 별도 보스 씬은 추가 연결·수용 검증을 요청합니다. 현재는 같은 테스트 씬을 맵마다 다시 읽으며 빌드 목록에 별도 보스 씬이 없습니다. 표만 수정한다고 씬이나 프리팹 참조가 자동 생성되지는 않습니다. 새 씬 연결은 준비 완료 후 진행합니다.

## 4. 정상 결과 확인

- 몬스터를 남겨도 일반 출구를 이용할 수 있어야 합니다. 마을 장부 조건·기획 잠금은 별개입니다.
- 이전 맵으로 돌아왔을 때 처치 기록이 유지되는지, 사망하면 마지막 저장 이후 처치만 되돌아오는지 확인합니다.
- 장부방 입구·복귀·보스 입장·서낭당 위치에서 떠 있거나 원점에 생성되지 않는지 확인합니다.
- 새로운 공간의 실제 왕복은 아직 검증되지 않았습니다. 문제가 있으면 Stage ID·프리팹 이름·스폰 파일·이동 방향·첫 오류를 전달합니다.
