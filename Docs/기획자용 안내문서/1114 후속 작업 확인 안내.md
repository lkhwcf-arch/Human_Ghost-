# 1114 후속 작업 확인 안내

기준일: 2026-11-14. 코드 반영과 실제 게임 수용 확인은 다릅니다. 현재 판정은 [1114 대응 현황](../개발자용%20설계문서/1114%20통합%20전달%20대응%20현황.md), 구현 책임은 [후속 구현 설계](../개발자용%20설계문서/1114%20전투·입력·리깅%20후속%20구현.md)를 봅니다.

## 1. 조작 변경

상호작용은 두 조작 방식 모두 F입니다. 입력 파일과 실행 중 키 지정 모두 바꿨습니다. NPC 대화·서낭당·장부·처형에서 F가 작동하고 E가 작동하지 않는지 확인합니다. F 전용 그림이 오기 전에는 F 글자 안내를 사용합니다. 패드 위 방향은 유지됩니다.

매달리기는 Player.HangAuto=Y를 사용합니다. 점프·낙하 중 턱의 잡기 범위에 들어오면 키 없이 잡습니다. 아래 입력으로 놓은 직후 같은 턱을 다시 잡지 않고, 범위를 벗어난 뒤 다시 접근하면 잡을 수 있어야 합니다. 가마터 Hang_* 6곳을 모두 확인합니다.

약초 중에는 800ms 동안 좌우 이동이 없어야 하고, 종료 뒤 이동이 돌아와야 합니다. 서낭당은 화면 동안 앉아 있고, 닫기 후 일어서는 약 0.6초 동안 이동이 막히며 끝나면 움직여야 합니다. 대화·오류·일시정지를 겹쳐도 잠금이 남지 않아야 합니다.

## 2. 전투와 보상

~~~mermaid
flowchart LR
    A[적 공격 읽기] --> B[패링]
    B --> C[일반몹 반격 기회·체세 감소]
    C --> D[자세 붕괴]
    D --> E[F로 처형]
    E --> F[기본 보상+추가 처형 보상]
~~~

보스 패링은 현재 기획대로 체세 피해이며 일반몹 경직 규칙을 보스에게 새로 넣지 않았습니다. 잡몹 머리 위에는 전투 중 체세가 표시되도록 연결했습니다. 표시 색·크기는 실제 장면에서 확인해야 합니다.

추가 보상은 ExecuteReward의 엽전·회복·오염 값을 사용하고 스폰별 한 번 지급합니다. 일반 처치에는 추가 처형 보상이 없어야 합니다. HP가 가득 차면 회복 효과를 불필요하게 띄우지 않습니다. 저장→처형→사망→복귀에서 이력이 저장 상태와 맞고, 다시 등장한 몬스터를 처형할 수 있어야 합니다. 아이템 지급은 현재 공급값 0이며 인벤토리 기능을 새로 만든 것은 아닙니다.

인식은 MonsterAggro 최신값을 사용합니다. 다른 높이에서는 쉽게 발견하지 않고, 추적 해제 후 원래 자리로 걸어오며 HP는 유지·체세는 회복해야 합니다. 공격·돌진·잡기·노출·처형 도중 경계 이탈로 동작이 끊기면 안 됩니다. 복귀 지연 중 피격은 즉시 인식 예외입니다.

## 3. 리깅과 화면

지게귀 일반형·투척형 달리기는 리그입니다. 이동·돌진 때 달리고, 피격·패링·노출·처형·사망 시 해당 기존 동작으로 돌아와야 합니다. 방향을 바꿔도 관절이 뒤집히거나 발이 바닥에서 밀리지 않는지 확인합니다. 쇄문아비 2페이즈는 Test 공급 부품 기반 리그이며 두 번의 도약에서 착지와 충격 판정이 일치해야 합니다.

보스방 상단 발판과 대응 충돌체는 껐습니다. 바닥에서 보스와 싸운 뒤 오른쪽 마무리 관문까지 걸어갈 수 있어야 합니다. 엔딩·관문·검은 마무리 화면은 기존 공통 기능입니다.

언어는 옵션에서 한국어·영어를 선택합니다. UI_Lang을 통해 주요 화면 문구를 읽습니다. 저장·취소, 메뉴를 연 상태에서 변경, 영어 긴 문구·줄바꿈·버튼 잘림을 확인합니다. 타이틀 메뉴는 번역 가능한 글자로 표시하고 로고는 유지합니다. 스킬 이름은 숨겼고 보스 이름은 키웠습니다. 시작 시 시험용 조작 안내는 숨겼습니다.

## 4. 검증 순서·남은 공급

1. Unity MCP 재연결·컴파일·콘솔을 확인한 뒤 게임을 실행합니다. 실제 사용자 저장을 보존하는 시험 환경을 사용합니다.
2. F와 자동 매달리기를 먼저 확인합니다.
3. 약초·서낭당·패링·처형 보상·체세·몬스터 복귀를 확인합니다.
4. 보스방 상단 제거·공격 판정·2페이즈·오른쪽 관문을 연속 확인합니다.
5. 타이틀·옵션·저장·상호작용·HUD의 두 언어와 하단 정렬·맵 이름을 확인합니다.
6. 일반 경로로 8002+8006의 처치 보상과 갈림길 도착 보상을 확인합니다. 테스트 바로 이동은 앞 맵의 처치 기록이 없어 0혼이 될 수 있습니다.

자동 검사는 데이터 8,885개·코어 1,773개와 전체 소스 컴파일을 통과했습니다. 전체 게임 Play와 실행파일 확인은 남아 있습니다. 지게귀 분리 Play와 세 UI 프리팹 언어 전환 확인을 전체 게임 수용 완료로 보지 않습니다.

### 보스 애니메이션 직접 보기

1. `Assets/5.Animation/Characters/CharacterAnimationPreview.unity`를 열고 Play를 누릅니다.
2. 오른쪽 두 마리가 쇄문아비 1페이즈(스프라이트)·2페이즈(리그)입니다. 아래 글자가 지금 재생 중인 동작 이름입니다.
3. 초록 선이 게임 바닥 높이입니다. 발·팔이 선에 닿는지, 선 아래로 파고들지 않는지 봅니다.
4. 2페이즈의 프레임 수·대기/걷기 속도는 `BossGameplay` 프리팹의 `BossPhaseTwoView` 값(리그 표시 프레임 10, 대기·걷기 재생 배율 0.8)을 그대로 씁니다. 값을 바꾸면 이 씬과 게임이 같이 바뀝니다.
5. 공격 동작의 실제 판정 타이밍은 게임 보스방의 F8 보스 시험 창에서 패턴을 골라 확인합니다.

### 이번에 바뀐 화면

- 장부방에서는 ↑/↓ 위아래 보기가 동작하지 않습니다(방 밖 그림이 보이던 문제). 다른 맵은 그대로입니다.

- 몬스터·보스 머리 위의 개발용 글자(이름·번호·상태·체력)를 숨겼습니다. 잡몹 체세 막대는 1114 전달대로 유지합니다(11/14 확정). O11 HUD R3의 "머리 위 표시 없음" 문구는 기획서 쪽 갱신이 필요합니다.
