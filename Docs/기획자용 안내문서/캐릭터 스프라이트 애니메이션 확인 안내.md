# 캐릭터 스프라이트 애니메이션 확인 안내

기준: 2026-11-09. 결과물은 `Assets/5.Animation/Characters/`에 있습니다. 공급 PNG·CSV·JSON은 수정하지 않았고, 기존 Sprite ID 620개를 보존하며 새 셀 프레임을 추가했습니다.

## 육안 확인

1. `CharacterAnimationPreview.unity`를 열고 Play를 누릅니다. Player·Husugwi·Jigegwi·Swaemunabi 네 캐릭터가 나란히 동작을 순환합니다. 게임 저장·전투·데이터 초기화는 없는 독립 확인 씬입니다.
2. 각 캐릭터 폴더의 `Clips/*.anim`에서 동작을 확인합니다. 총 52개이며 프리뷰용 컨트롤러와 `*AnimationPreview.prefab`도 같은 폴더에 있습니다.
3. 특정 클립은 해당 미리보기 프리팹을 열고 Animation 창의 클립 목록에서 선택합니다. 미리보기 컨트롤러는 동작 순환용이며 본게임의 상태를 결정하지 않습니다.

## 상태와 호출

- `State.csv`의 ID/Key와 생성된 StateKey를 대조해 클립을 연결했습니다. 상태는 기존 코어가 선택하고 표시만 교체합니다. 새 CSV 행이나 애니메이션 테이블을 만들지 않았습니다.
- 사다리 루프는 별도 LadderClimb 클립으로 위/아래/정지를 표시합니다. Map_ME 연결은 [이동·UI 안내](하단%20점프·사다리·신규%20인게임%20UI%20확인%20안내.md)를 따릅니다.
- 기본 10fps입니다. Idle/Walk/Run/Hang/Stun은 반복하고, 공격·피격·사망 등은 한 번 재생 후 마지막 프레임을 유지합니다. 공격과 플레이어 피격/구르기/착지는 기존 동작 시간에 맞춰 표시 길이를 조정합니다.
- 플레이어 Attack3는 Attack1, Attack4는 Attack2 원본을 재사용합니다. Bound는 Hit, Stun/Exposed는 CritHit를 사용합니다. 공중 Attack1은 JumpAttack을 사용합니다.
- 보스 Attack2는 기존 연결대로 attack2+attack5를 이어 재생하고, Attack3는 attack6입니다. Skill1은 기존 Attack1 대체 표시를 유지합니다. 사망 원본이 없어 Dead는 Hit의 마지막 프레임을 고정합니다. 별도의 2페이즈 리그 시험 자산은 변경하지 않았습니다.
- Run·EvadeForward·BackRoll·Execute2는 전용 클립과 미리보기를 준비했습니다. CSV 상태/실제 변형 선택 규칙이 없는 동작에 새 입력이나 선택 정책을 추가하지 않았습니다.
- Climb/Save는 State.csv에 해당 키가 없습니다. 실제 올라가기 성공·서낭당 휴식 저장 성공 알림으로 연결하며 공격·피격 상태가 되면 표시를 중단합니다.
- 자동 발소리와 기존 사운드 호출은 유지합니다. 현재 클립 샘플링은 AnimationEvent를 실행하지 않으므로 발소리의 최종 발 접촉 동기화는 별도입니다.

## 검증

- Unity 격리 검사 1,552개: 52개 클립·셀 프레임·55개 상태 연결·중간 프레임·반복/마지막 고정·발 위치·Climb/Save·구독 해제 확인.
- 독립 미리보기 실제 Play에서 네 캐릭터의 서로 다른 상태/프레임 진행과 화면 확인. 코어718·데이터940 통과. 본게임 전체 전투·사망·이동 왕복 검증과 게임 빌드는 별도입니다.
- 원본에서 자동 분할이 몸체·파편을 나누거나 프레임을 합친 부분은 새 셀 분할로 보완했습니다. 원본에 이미 잘린 경계·번짐은 그림 제작 쪽 후속입니다.
