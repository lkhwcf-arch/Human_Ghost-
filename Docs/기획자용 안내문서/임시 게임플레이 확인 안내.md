# 임시 게임플레이 확인 안내

2026-11-04 c7100e3 기준입니다. Preview는 실제 게임을 확인하는 임시 조립이며 운영 저장·풀·최종 애니를 대신하지 않습니다. [최신 현황](../%EA%B0%9C%EB%B0%9C%EC%9E%90%EC%9A%A9%20%EC%84%A4%EA%B3%84%EB%AC%B8%EC%84%9C/%ED%98%84%EC%9E%AC%20%EA%B5%AC%ED%98%84%EA%B3%BC%20%EA%B2%80%EC%A6%9D%20%ED%98%84%ED%99%A9.md)과 [회의 회귀 검사](../%EA%B0%9C%EB%B0%9C%EC%9E%90%EC%9A%A9%20%EC%84%A4%EA%B3%84%EB%AC%B8%EC%84%9C/%EB%82%A8%EC%9D%80%20%EA%B5%AC%ED%98%84%EA%B3%BC%20%EA%B2%80%EC%A6%9D%20%EC%9E%91%EC%97%85.md)를 함께 봅니다.

## 1. 어디서 확인하나요?

- 타이틀부터: Assets/1.Scene/Title.unity에서 새로 시작합니다. 임시 로딩 뒤 MapDohwagolTest로 갑니다.
- 맵 확인: Assets/1.Scene/MapDohwagolTest.unity를 실행합니다. StageContentSet과 PreviewSession이 맵·플랫폼·몬스터·출구를 연결합니다.
- 독립 전투: Assets/1.Scene/GameplayPreview.unity를 사용합니다. 같은 코어를 사용하더라도 씬별 연결과 시작 상태는 다를 수 있습니다.

현재 맵2·3 실행은 Assets/Data/SpawnTemp의30마리 JSON을 직접 참조하며 협곡은매복4마리를 포함합니다. 정식 배포 경로 Assets/Data/Json/spawn의각4마리와 다릅니다. 실행 중 임시 진행이 어떤 스테이지를 선택했는지 확인합니다.

## 2. 조작과 상태

| 입력 | 현재 확인할 기능 |
| --- | --- |
| 이동·점프·공격·구르기 | 연결된 InputAction과 PreviewKeyLayout 설정을 기준으로 확인 |
| E/W 상호작용 | 매달림·보스 해체·가까운 대상 선택 등 우선순위 확인 |
| Z | 결박 가르기. 해금 전 거부·관문에 명중 시 개방 |
| 텍스트박스의 X | 다음 줄. 공격으로 새지 않는지 확인 |
| H | 개발 확인용 피해 입력 |
| Esc/패드 Start | 일시정지. 죽음·암전·해체·스킬 중 금지 |
| F5 | 실제 저장 런타임 미연결이므로 현재 씬에서 정상 사용 가능하다고 보지 않음 |

기존 키 배치B(J/K/L) 도구는 확인용입니다. 회의에서 요청한 최종 튜토리얼 키 기준은 기획과 따로 맞춥니다. R수동 해체 완료 키는 최신 코드에서 제거됐으며 임시900ms 뒤 자동 완료합니다. 최종 연출이 들어오면 실제 완료 신호로 바꿔야 합니다.

## 3. 최신 수정의 회귀 순서

1. 해체를 반복하고 양쪽 상태·입력이 정상 복귀하는지 확인합니다.
2. 보스방에서 사망한 뒤 서낭당을 거쳐 재입장합니다.
3. 결박 관문을 점프로 넘을 수 없는지, Z안내와 스킬 개방이 되는지 확인합니다.
4. 맵2→맵1·맵3→맵2 복귀에서 도착 앵커·HP·약초가 유지되는지 확인합니다.
5. 몬스터 사망 뒤 타격·보상·피해가 반복되지 않는지 확인합니다. 사망 불은 현재 설정0입니다.
6. 매복은 트리거 전 비활성이고 출구는 예정 개체까지 처리한 뒤 열리는지 확인합니다.
7. 캐릭터 각 상태의 발 위치·오브젝트 지면·일반/치명 명중 진동·설정OFF를 확인합니다.

사망 재시작은 자원 이동 유지와 달리 HP/약초를 새로 채우는 흐름입니다. 재방문 잡몹 정책은 사용자 이전 방향과 K16 사이에서 확인이 필요하므로 현재 재생성을 최종 규칙으로 문서화하지 않습니다.

## 4. 표시와 수명 경계

플레이어·몬스터는 상태별 대표 프레임을 쓰며 실제 전체 애니 연결과 다릅니다. 발 정렬은 프레임 정점 하단을 맞추는 임시 방식이므로 투명 여백·발 위치를 실제 화면에서 확인합니다. 사각형은 표시를 끄더라도 판정에 사용할 수 있으므로 임의 제거하지 않습니다.

GameplayPreview는 현재 초기화·스테이지·입력·판정·표현을 조립합니다. 반복 이름표·프레임 선택 갱신, 정적 PreviewSession, 부분 생성 실패 정리는 운영 모듈 전환 시 개선 대상입니다. 몬스터 Instantiate는 풀링 구현이 아닙니다.

## 5. 검사 결과를 읽는 방법

최신 검증 근거는 [현재 구현과 검증 현황](../개발자용%20설계문서/현재%20구현과%20검증%20현황.md)을 따릅니다. 과거 `_exitAnchor` 컴파일 실패 설명은 현재 상태가 아닙니다. 이번 문서 점검에서는 실제 Play·키 주입·빌드 재검증을 실행하지 않았습니다. 과거 메뉴 검사 결과는 당시 범위의 기록이며 회의 버그 해결 증거로 대신하지 않습니다.
